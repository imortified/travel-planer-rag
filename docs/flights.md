# Поиск и сохранение перелётов

Этап от 25 октября 2026. Ветка `feature/flight-search-and-selection` продолжает
не слитую `experiment/aviasales-data-access`; реализация — `f3b30ec`.
[Пилот доступа](aviasales-data-access.md) остаётся отдельной CLI-проверкой.

Уточнение интерфейса: `fix/selected-flight-budget-entry`, поверх ещё не слитой
`feature/warm-cool-dark-themes`. Выбор рейса и ввод общей стоимости теперь явно
разделены в самой карточке; прежние сохранённые снимки не переписываются.

## Пользовательский сценарий

1. Создайте или загрузите группу, укажите реальный город и календарные даты поездки.
2. В блоке «Как доберёмся · перелёты» начните вводить город или аэропорт вылета
   и выберите подсказку. «Москва · все аэропорты (MOW)» ищет по городу одним запросом;
   «Шереметьево (SVO)» ограничивает вылет конкретным аэропортом. При необходимости
   используйте «Ввести IATA-код вручную». Задайте дату вылета и при необходимости
   обратный вылет. Назначение определяется
   городом: Lisbon/Sintra → LIS, Porto → OPO. Для Синтры трансфер нужен отдельно.
3. При необходимости включите фильтр без пересадок или смените регион выдачи RU/US.
4. Нажмите «Найти перелёты». Карточки содержат наблюдение цены, авиакомпанию,
   номер рейса из ответа, даты вылетов со смещением часового пояса, число пересадок
   и ссылку повторной проверки на Aviasales, если она есть в ответе.
5. Выберите перелёт. Включится бюджет всей поездки. **Общую стоимость всех билетов
   для всех участников введите вручную** прямо в карточке выбранного рейса,
   в поле «Общая стоимость выбранного перелёта на всю группу, EUR».
   Оно связано с полем «Перелёты на всю группу» в расходах: это одна сумма,
   которая учитывается один раз. Без неё новый расчёт с выбранным рейсом не запускается.
   Учитывайте оба направления и нужный багаж. Наблюдение цены не переносится
   автоматически и не умножается на участников.
6. Отдельно укажите жильё, наземный транспорт и резерв. Постройте маршрут;
   выбранный перелёт и оценка расходов сохраняются вместе с поездкой.

## Поиск города и пересадки

Ветка `feature/flight-city-selection` продолжает ещё не слитую
`fix/automatic-period-catalog-loading`. `GET /api/v1/flight-places?term=Москва`
требует входа и обращается к публичному Travelpayouts `places2` с `locale=ru`
и типами `city`/`airport`. Токен и данные пассажиров в подсказки не передаются.
Есть задержка ввода 350 мс, защита от запоздавших ответов и выбор клавишами
стрелок/Enter. Изменение текста снимает прежний выбор; произвольное название
нельзя отправить вместо выбранного кода. Если сервис недоступен, остаётся ручной ввод.
Ответы проверяются и кэшируются Redis на сутки в пространстве `flight_places`.

Городской код передаётся в `prices_for_dates` без обхода аэропортов отдельными
запросами. `unique=false`, сортировка по цене, максимум десять наблюдений;
это не полный перечень аэропортов или всех доступных билетов. Фактический аэропорт
из ответа показан в карточке. Ответ может содержать код города в `origin`,
а код выбранного аэропорта в `origin_airport`; оба случая проверяются.

Если «Только без пересадок» выключено, допустимы пересадки. Минск → Лиссабон
с пересадкой и Москва → Лиссабон имеют разные точки отправления. Система не
подменяет город и не складывает отдельные билеты: нет подтверждённых сегментов,
стыковок и времени прибытия. Можно увидеть количество пересадок, а их города
и условия нужно перепроверить по ссылке поставщика. Дорога до другого города
вылета учитывается пользователем отдельно.

Источники: [подсказки](https://support.travelpayouts.com/hc/en-us/articles/360002322572-Autocomplete-API-for-countries-cities-and-airports-by-Aviasales),
[параметры Data API](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API).

Пустое поле стоимости означает неизвестную сумму; ноль — отсутствие расходов.
Карточка выбранного рейса сообщает, что цена ещё не учтена; после ввода суммы
предлагает выполнить «Построить маршрут». Уже показанный результат не обновляется
сам при изменении формы. Для старых сохранённых расчётов с выбранным рейсом и
неизвестной ценой в разбивке расходов выводится отдельное предупреждение:
перелёт не вошёл в учтённую сумму. API сохраняет совместимость с такими снимками.
Если перелётов нет, можно указать 0 без поиска. Поиск также доступен без возраста:
этот метод поставщика не принимает состав пассажиров. Возраст, если указан,
сохраняется в истории выбора без назначения детских авиационных скидок.
Изменение дат, города, состава или параметров поиска сбрасывает выбор;
введённые вручную суммы остаются оценками, их нужно перепроверить.

## Источник и ограничения

Используется [Aviasales Data API, prices_for_dates](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API).
Это кэш прошлых поисков поставщика. Время `fetched_at` показывает, когда наше
приложение получило ответ; дата первоначального нахождения цены неизвестна и
сохраняется как `source_found_at=null`. Цена не подтверждает наличие билетов,
стоимость для группы, багаж, детские тарифы или окончательные условия покупки.
Пустая выдача означает отсутствие подходящих записей в кэше, а не отсутствие рейсов.
По датам метод может возвращать ограниченный набор, а не все существующие рейсы.

Полные сегменты и проверенное время прибытия отсутствуют. Поля продолжительности
из кэша не используются для вычисления прибытия или изменения дня посещений.
Маршрут начинается в существующей центральной точке города; трансфер, очереди,
аэропортовый запас времени и возможность посещений в первый/последний день нужно
проверить вручную. Показываемый номер относится к записи поставщика и не описывает
все сегменты при пересадках. Гражданство и транзитные требования по сегментам
перелёта не проверяются текущим визовым справочником Португалии.

Ссылка ведёт на поиск Aviasales из ответа поставщика. Она не является подтверждением
того же тарифа и не оформляет бронь. Партнёрская атрибуция продаж не добавлена.

## Запуск и конфигурация

Токен хранится только в корневом игнорируемом `.env`:

```dotenv
TRAVELPAYOUTS_API_TOKEN=
AVIASALES_CACHE_TTL_SECONDS=3600
AVIASALES_TIMEOUT_SECONDS=30
```

Для текущего локального окружения токен уже сохранён. В Git и `.env.example`
его значения нет. В приложении используется `SecretStr`; токен передаётся только
сервером в `X-Access-Token` на фиксированный HTTPS endpoint, без параметра в URL.
Поставщику отправляются аэропорты, даты, валюта, регион и фильтр пересадок.
Имена, возраст, даты рождения и внутренние ID участников не отправляются.
Ссылки ограничены страницами поиска на домене Aviasales, редиректы API отключены.

Примените миграцию `0015` (локально уже применена):

```powershell
cd backend
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m app.run --reload
```

Frontend запускается прежней командой на 3001; API остаётся на 8001.
Дополнительных библиотек не требуется. Для смены токена перезапустите backend.

## API и хранение

`POST /api/v1/groups/{group_id}/flight-searches`, пример тела:

```json
{"destination":"Lisbon","origin":"WAW","departure":"2026-11-15","return_date":"2026-11-22","market":"ru","direct":false}
```

Ответ содержит `observation_id`, `options`, `passengers`, `search`, `fetched_at`,
`expires_at`, `cache` и статус `observations` или `empty`. Нормализованная
`observed_price` — целые евроценты. Доступно до десяти записей на запрос.
Группа без участников отклоняется. Дата вылета должна быть текущей/будущей;
обратный вылет — не раньше первого, в пределах года от него.

В `POST /api/v1/groups/{id}/trips` добавляются поля:

```json
{
  "destination":"Lisbon",
  "travel_date":"2026-11-15",
  "end_date":"2026-11-17",
  "budget":200000,
  "budget_settings":{"lodging":20000,"transport":5000,"flights":40000,"transport_scope":"ground_only","reserve":10000},
  "flight_plan":{"observation_id":"UUID из ответа","option_id":"ID выбранной записи из options"}
}
```

Перелёт должен покрывать календарные даты поездки: вылет не позже первого дня,
обратный вылет — не раньше последнего. Это проверка дат, не фактического времени
доступности для посещений. В одну сторону `return_date=null`, обратная часть не проверяется.

Redis хранит валидированные ответы по ключу всех параметров запроса; токена и ID
группы в ключе нет, поскольку ответ не зависит от состава нашей группы.
TTL по умолчанию 3600 секунд, допустимые настройки 60–86400 секунд. Попадание
в кэш сохраняет исходные fetched/expiry. `expires_at` ограничивает срок прикрепления
к новой поездке и не обещает сохранение цены. При наличии срока от поставщика
используется более ранний срок. Устаревший кэш не выдаётся после отказа источника.
При отказе Redis запрашиваются свежие данные. Одна попытка, без повтора 429.
Ошибки и неподходящие ответы — 503, ручная оценка транспорта остаётся доступной.

PostgreSQL хранит `flight_search_observations`: группа, JSON, контрольная сумма и срок.
Выбор по ID проверяет группу, целостность, срок, город, даты, состав/возраст и вариант.
Изменение группы во время загрузки — 409; недопустимый/истёкший выбор — 422.
Это привязка данных к группе; аутентификация пользователей пока отсутствует.
В `trip_requests.flight_snapshot` сохраняется неизменный снимок. История и
пересчёт старого запроса не обновляют цену и не требуют живого API.

## Бюджет и совместимость

Поле `budget_settings.flights` — отдельная ручная общая оценка. Оно допустимо
только при `transport_scope=ground_only`: `transport` тогда включает наземные
расходы и трансферы, без авиабилетов. Старые запросы без нового поля имеют
`transport_scope=all_transport` и прежний смысл транспорта. История старых расчётов
не переписывается. Новая форма всегда использует разделение транспорта.

Все три алгоритма получают бюджет остановок после вычитания жилья, наземного
транспорта, перелётов и резерва. В `known_total` входят расходы без резерва.
Незаполненная стоимость перелётов остаётся в `unknown_categories`, а не берётся
из справочной цены. В LLM-объяснение передаются соответствующие ограничения,
версия композиции фактов — `grounded-explanation-v9-flights`.

## Разделение ошибок поставщика

Ветка `fix/aviasales-query-errors` продолжает `feature/automatic-food-catalog-and-estimates`.
Отказ поставщика с HTTP 400/422 возвращается пользователю как HTTP 422 с сообщением
о параметрах поиска. Он больше не превращается в сообщение о недоступности API.
401/403 отдельно обозначают отказ доступа к API, 429 — лимит запросов. Ошибки сети
и сервера сохраняют сообщение о недоступности. Ошибочные ответы не кэшируются,
автоматических повторов нет. Текст поставщика никогда не передаётся в UI: из него
выбирается только имя поля для подготовленной подсказки, без секретов и исходного тела.

28 октября 2026 полный набор с PostgreSQL, Redis и Qdrant: 839 passed; четыре
дополнительных теста адаптера RAGAS прошли в отдельном evaluation-окружении.
37 frontend-тестов, TypeScript и production-сборка прошли. Это проверки адаптера,
а не новая оценка качества LLM-судьи. На копии сохранённых настроек недельного
маршрута API вернул HTTP 201 и три допустимых варианта с ежедневными обедами;
все записи этого теста откатились. Прямой запрос MSQ/WAW → LIS на 5–10 ноября
вернул успешную пустую выдачу; исходный HTTP 400 на этих параметрах не повторился.
