# Статические визовые правила MVP

Реализован справочный визовый отчёт для туристической поездки в Лиссабон / Португалию
на 1–14 дней. Гражданства: Беларусь, Россия, Украина, Грузия, Германия,
Великобритания (British citizen), США. Правила задаются в `data/visa-rules.json`,
применяются детерминированно в `backend/app/visa.py`, без LLM и внешних запросов.

Требование ТЗ о визовых сроках реализовано **как предупреждение**:
`VisaFeasibilityValidator` в пояснительной записке допускает «жёсткий или предупреждение».
`result.is_feasible` и независимый валидатор маршрута проверяют бюджет и расписание;
они не подтверждают готовность документов. Визовый отчёт хранится отдельно.

## Данные и интерфейс

У каждого участника раскрывается «Гражданство и документы»: гражданство используемого
документа, обычный/специальный паспорт, биометрический признак для UA/GE,
наличие особого основания (например, ВНЖ), наличие краткосрочной визы со слов участника.
Неизвестные поля остаются неизвестными; имена и LLM-запрос не определяют гражданство.
Номера документов, сканы и биометрические данные не собираются.
В параметрах поездки выбирается цель въезда: туризм / иная / не уточнена.

Кнопка «Проверить визовые условия» работает до сохранения группы и без БД.
При изменении дат, направления, цели, имён или документов прежний предварительный
отчёт скрывается. Сохранённый результат справа остаётся снимком своего запроса.

Для BY/RU при обычном паспорте и отсутствии особого основания показывается требование
визы; для UA/GE освобождение применяется только при подтверждённом обычном
биометрическом паспорте. Явно небиометрический обычный паспорт UA/GE требует визы
в рамках этой области; специальные основания оцениваются вручную.
Для DE применяется правило гражданина ЕС. Для GB поддерживается полный паспорт
British citizen, остальные британские статусы требуют ручной проверки.
Для US/GB требуется подтверждение обычного паспорта и отсутствия особого основания.

Неизвестное/неподдерживаемое гражданство, специальные документы/основания, отсутствие
дат, другая цель, прошедшие даты и данные вне окна пересмотра возвращают
`requirement=unknown`, `status=needs_review`. Условие из справочника в таком случае
помечено как справочное, его применимость не подтверждается.
Для Demo City отчёт `not_applicable` и не отображается.

Даже при указании «есть виза» её требование остаётся `required`, а наличие считается
непроверенным сообщением участника. Действительность документов, число въездов,
предыдущие пребывания и лимит 90/180 не вычисляются. Отчёт не является разрешением
на въезд. ВНЖ, второе гражданство, долгосрочные визы, работа, транзит и специальные
паспорта находятся за пределами автоматической оценки.

## Сроки и актуальность

Начальная версия: `portugal-tourism-2026-10-23-v1`, источники проверены 2026-10-23,
повторная проверка данных проекта назначена до 2026-11-22. **Это политика пересмотра
справочника, не законодательно гарантированный период действия правил.**
И дата оценки, и весь период поездки должны находиться в этом окне; иначе требуется
ручная проверка. Дата оценки берётся на сервере в Europe/Minsk; клиент не передаёт её.

При требуемой визе и отсутствии подтверждённого сообщения о её наличии отчёт показывает:

- число календарных дней до начала поездки;
- обычную дату подачи не позднее чем за 15 дней до поездки;
- обычное/продлённое рассмотрение: BY — 10/30 календарных дней по статье 7 соглашения,
  RU — 15/45 по общему порядку после полной приостановки упрощённого соглашения;
- предупреждения о коротком сроке подачи, обычном рассмотрении или риске продления.

Для небиометрических паспортов UA/GE срок рассмотрения не задан: нельзя без проверки
переносить общий срок поверх возможных соглашений. Показывается только срок подачи.
Рассмотрение начинается после приёма заявления и необходимых документов; запись,
доставка, сборы и срочные исключения не рассчитываются. Даже достаточный запас дней
не гарантирует своевременной выдачи визы. Визовые сборы не входят в бюджет POI.

## Источники

- [Регламент ЕС 2018/1806, приложения I и II, консолидированный текст](https://eur-lex.europa.eu/eli/reg/2018/1806/2025-12-30/eng):
  визовые списки и биометрические условия освобождения.
- [Еврокомиссия: визовая политика](https://home-affairs.ec.europa.eu/policies/schengen/visa-policy_en):
  статус соглашений с Беларусью/Россией и ограничения для специальных паспортов Грузии.
- [Соглашение ЕС — Беларусь, статья 7](https://eur-lex.europa.eu/eli/agree_internation/2020/752/oj/eng):
  сроки рассмотрения 10/30 дней.
- [Еврокомиссия: подача шенгенского заявления](https://home-affairs.ec.europa.eu/policies/schengen/visa-policy/applying-schengen-visa_en):
  общие сроки рассмотрения 15/45 дней.
- [Португалия: краткосрочная шенгенская виза](https://www.gov.pt/servicos/pedir-um-visto-schengen-de-curta-duracao):
  сроки подачи и ограничения визы как документа.
- [EEAS: ЕС и Грузия](https://www.eeas.europa.eu/georgia/european-union-and-georgia_en),
  [Еврокомиссия: визовая либерализация](https://home-affairs.ec.europa.eu/policies/international-affairs/engagement-partner-countries/eastern-partnership/visa-liberalisation-moldova-ukraine-georgia-and-armenia_en):
  обычные биометрические паспорта и область освобождения.
- [Your Europe: документы граждан ЕС](https://europa.eu/youreurope/citizens/travel/entry-exit/eu-citizen/index_en.htm).
- [GOV.UK: въезд в Португалию](https://www.gov.uk/foreign-travel-advice/portugal/entry-requirements):
  область полного паспорта British citizen.

URL источников сохранены у каждого правила и показаны в интерфейсе.
При обновлении справочника необходимо проверить официальные источники, условия и
сроки, изменить `version`, `checked_on`, `review_by` и прогнать тесты. Прошедший срок
пересмотра нельзя просто продлить без проверки. Автоматического обновления нет.

## API и хранение

Нужна миграция `0008`: из `backend` выполнить
`.\.venv\Scripts\python.exe -m alembic upgrade head`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/v1/visa-rules` | Версия, область, источники и семь правил |
| `POST /api/v1/visa-check` | Предварительный отчёт без сохранения и без БД |
| `PUT /api/v1/groups/{gid}/members/{uid}/travel-profile` | Замена профиля документов участника в группе |

Пример предварительного запроса:

```json
{
  "destination": "Lisbon",
  "travel_date": "2026-11-01",
  "purpose": "tourism",
  "travellers": [{
    "name": "Анна",
    "profile": {
      "citizenship": "BY",
      "passport_kind": "ordinary",
      "special_entry_basis": false,
      "visa_status": "not_held"
    }
  }]
}
```

`TravelProfile` и предварительный запрос запрещают лишние поля; страны — двухбуквенные
коды, булевы признаки строгие. Неподдерживаемые двухбуквенные коды дают ручную проверку.
Новый `TripInput.purpose` по умолчанию `tourism`; старые поездки получают `unknown`.
Профиль хранится в PostgreSQL `memberships.travel_profile`, копируется в
`TripRequest.participants_snapshot` и не меняется вслед за текущим профилем группы.
Каждый новый расчёт сохраняет `visa_report` с версией правил, датой оценки, причинами,
источниками и сроками в `route_sets` и во всех `route_options`. Отчёт сохраняется и
при отсутствии допустимых вариантов. При чтении истории он не пересчитывается.
Старые маршруты сохраняют `visa_report=null`. Правила находятся в Git, отчёты — в
PostgreSQL; Redis и Qdrant в визовой проверке не участвуют.

LLM получает только вычисленный факт о количестве визовых требований, освобождений
и ручных проверок. Этот факт обязателен в объяснении с `grounded-explanation-v3-visa`;
изменение или пропуск вызывает проверяемый шаблон. LLM не применяет право самостоятельно.

## Проверки

`tests/test_visa.py` проверяет гражданства, условие биометрии, особые случаи, даты,
окно пересмотра, сроки, строгий API и защиту объяснений. PostgreSQL-тесты дополнительно
проверяют сохранение профиля, снимки, единый отчёт вариантов, историю и старые записи.
Запуск из `backend`: `$env:RUN_DB_TESTS='1'; .\.venv\Scripts\python.exe -m pytest`.

Ручной сценарий: Анна BY без визы и Максим UA с обычным биометрическим паспортом,
без особых оснований, Лиссабон 25 октября 2026, оценка 23 октября.
Показаны требование визы/нехватка времени для Анны и условное освобождение для Максима.
При неизвестной биометрии у Максима нужна ручная проверка. Изменение поля скрывает
предыдущий предварительный отчёт; сохранённый маршрут открывает свой прежний снимок.

Итог этапа: 185 тестов прошли с PostgreSQL, Qdrant и Redis; Ruff и проверка форматирования,
`alembic check`, `uv lock --check` и production-сборка Next.js прошли.
Ручной расчёт создал три варианта и сохранённый визовый отчёт; объяснение через настоящий
Qwen3-4B / llama.cpp вернулось в режиме `llm` с проверенными фактами, включая визовый.
