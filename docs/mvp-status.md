# Выполнение MVP по пункту 3.3 ТЗ

Статус после добавления многодневного планирования. Рабочий прототип ещё не является
полным MVP по исходному ТЗ. Наличие тестов не заменяет выполнение требований.

| Требование | Состояние |
| --- | --- |
| Одиночный/групповой запрос до 6 участников | Реализовано; агрегация интересов упрощённая |
| Один город на поездку | Реализовано; реальный источник ограничен центром Lisbon |
| Структурированный ввод + LLM-парсинг | Форма реализована; LLM-парсинга нет |
| Маршрут по дням с бюджетом/часами/переездами | 1–14 дней реализованы; цены реального каталога пока только fee=no, транспортные расходы не включены |
| Проверка бюджета/времени/обязательных мест/виз | Всё кроме статических визовых правил реализовано |
| Рекомендованный маршрут + 1–2 альтернативы | Не реализовано; выбор алгоритма и история не заменяют альтернативы |
| LLM-объяснение выбора | Не реализовано; отчёт валидатора не является объяснением выбора |
| Веб-интерфейс + REST API | Минимальный сценарий реализован |

## Следующие этапы

1. Расширить и обогатить каталог одного города: разные категории, известные цены и
   проверяемые часы работы. Это нужно для содержательной многодневной поездки.
2. Генерировать разные допустимые альтернативы и показывать их сравнение.
3. LLM-парсинг с уточнением недостающих параметров и объяснения по фактам алгоритма.
4. Статический визовый справочник с источниками и датами актуальности.
5. Карта, завершение UX и приёмочные сценарии по каждому требованию.

Многодневная модель, ограничения и алгоритмы описаны в multiday.md.
Авторизация, полноценный профиль участника, расширенный групповой консенсус,
погодный/событийный контекст и CI учитываются отдельно при сверке с остальными разделами ТЗ.
