# Выполнение MVP по пункту 3.3 ТЗ

Статус после добавления локального LLM-помощника. Рабочий прототип ещё не является
полным MVP по исходному ТЗ. Наличие тестов не заменяет выполнение требований.

| Требование | Состояние |
| --- | --- |
| Одиночный/групповой запрос до 6 участников | Реализовано; агрегация интересов упрощённая |
| Один город на поездку | Реализовано; реальный источник ограничен частью Lisbon и Ajuda |
| Структурированный ввод + LLM-парсинг | Реализованы форма, Qwen3-4B через llama.cpp, предварительный просмотр и уточнения; поддерживаемые категории ограничены |
| Маршрут по дням с бюджетом/часами/переездами | 1–14 дней, бесплатные и платные POI реализованы; транспортные расходы не включены |
| Проверка бюджета/времени/обязательных мест/виз | Всё кроме статических визовых правил реализовано |
| Рекомендованный маршрут + 1–2 альтернативы | Реализовано: до трёх разных допустимых вариантов, сравнение и сохранение набора; при нехватке вариантов возвращается меньше |
| LLM-объяснение выбора | Реализована проверяемая композиция фактов через LLM; свободный пересказ ограничен, при ошибке — шаблон |
| Веб-интерфейс + REST API | Минимальный сценарий реализован |

## Следующие этапы

1. Начальное расширение каталога выполнено: история, искусство, природа и проверяемые
   взрослые тарифы (catalog-v2.md). Расширение покрытия города и категория еды ещё нужны.
2. Альтернативы и сравнение реализованы (alternatives.md), включая общий бюджет и несколько дней.
3. LLM-парсинг, уточнения и объяснения реализованы через llama.cpp (llama-cpp.md).
   Эмбеддинги и полноценный RAG-поиск ещё не реализованы.
4. Статический визовый справочник с источниками и датами актуальности.
5. Карта, завершение UX и приёмочные сценарии по каждому требованию.

Многодневная модель, ограничения и алгоритмы описаны в multiday.md.
Авторизация, полноценный профиль участника, расширенный групповой консенсус,
погодный/событийный контекст и CI учитываются отдельно при сверке с остальными разделами ТЗ.
