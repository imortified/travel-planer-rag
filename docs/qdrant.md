# Векторное хранилище Qdrant

Ветка `feature/qdrant-storage` основана на `feature/semantic-retrieval`.
Векторный поиск перенесён из JSON-файлов в Qdrant. Эмбеддинги продолжает вычислять
Qwen3-Embedding-0.6B Q8_0 через отдельный llama.cpp на 8082. Чат-модель и API
планировщика сохраняют свои роли; новых миграций PostgreSQL для этого этапа нет.

## Запуск

Из корня проекта:

```powershell
docker compose up -d --wait qdrant
.\scripts\start-embeddings.ps1
```

Последняя команда занимает терминал. В другом терминале можно заранее заполнить
индекс для одного дня или периода (при поиске это также происходит автоматически):

```powershell
cd backend
.\.venv\Scripts\python.exe index_catalog.py --travel-date 2026-10-23
# Или: --travel-date 2026-10-23 --end-date 2026-10-25
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

Выбранный образ — официальный `qdrant/qdrant:v1.20.0`, закреплённый также по SHA256
в `compose.yaml`. REST API и dashboard: `http://127.0.0.1:6333/dashboard`.
Порт публикуется только на loopback, gRPC наружу не опубликован. Docker healthcheck
проверяет `/readyz`. Данные находятся в именованном volume `qdrant_data` с префиксом
Compose-проекта; контейнер монтирует его в `/qdrant/storage`.

`docker compose stop qdrant`, `restart qdrant` и обычный `down` сохраняют volume.
Не добавляйте `down -v`, если нужно сохранить данные PostgreSQL и Qdrant.
Volume обеспечивает сохранность при пересоздании контейнера, но не заменяет резервную копию.

Настройки в `.env.example`:

| Настройка | По умолчанию |
| --- | --- |
| `QDRANT_URL` | `http://127.0.0.1:6333` |
| `QDRANT_TIMEOUT_SECONDS` | `10` |
| `QDRANT_COLLECTION_PREFIX` | `travel` |
| `QDRANT_API_KEY` | пусто; для сервера, требующего авторизацию |

Backend использует REST через уже установленный httpx; дополнительный SDK не требуется.
При запуске backend внутри контейнера URL нужно изменить на `http://qdrant:6333`.

## Коллекции и обновления

- `travel_interests_v1` — четыре профиля категорий.
- `travel_places_v1` — описания POI и метаданные: ID, город, категория, источник,
  дата проверки, тип описания, версия корпуса и идентификатор модели.

Обе коллекции имеют 1024 измерения и метрику Cosine. Индексируется payload-поле
`embedding_identity`. При существующей несовместимой схеме приложение возвращает
ошибку и сохраняет коллекцию. Оно не удаляет и не пересоздаёт пользовательские индексы.
Для новой несовместимой схемы следует выбрать новый префикс коллекций и переиндексировать.

ID точки — UUID, зависящий от логического ID документа, отпечатка текста и полного
идентификатора модели (имя, ревизия, размерность, рецепт инструкции). Поэтому:

1. Повторная индексация неизменившихся документов не вызывает модель.
2. Изменение одного описания создаёт одну новую версию вектора.
3. Изменение источника, имени или версии корпуса без изменения текста обновляет
   только payload; вычислять вектор заново не нужно.
4. Смена модели создаёт отдельные точки; векторы разных моделей не смешиваются.

Запись выполняется с `wait=true`. Поиск не выгружает векторы документов в Python:
Qdrant возвращает оценки сходства, а описания и ссылки сервер берёт из текущего
проверенного каталога/корпуса. Пользовательский вектор используется только в запросе,
не сохраняется как точка.
Одновременное первое создание коллекции допускается: конфликт создания обрабатывается,
а временные ошибки готовности при чтении схемы получают до трёх ограниченных повторов.

Прежние JSON-файлы `.local/semantic-cache` больше не читаются и не используются как
резервный источник. Они оставлены на диске для совместимости с предыдущей веткой.
Новый индекс строится из исходных описаний и выбранной модели, а не импортирует
непроверенные старые файлы.

## Фильтрация и воспроизводимость

Каждый запрос синхронизирует только свои кандидаты и передаёт фильтр по их точным
UUID плюс идентификатору модели. Пригодность по дате, известным часам/цене/доступу
определяется каталогом до поиска; при планировании также учитываются исключения.
Закрытые, исключённые, удалённые из каталога места и предыдущие версии текста не
попадают в результаты даже при более высокой близости.

Для сохранения прежних порогов и результатов используется `exact=true` — точный
поиск cosine внутри Qdrant. Порог категории 0.55, отрыв 0.05 и порог описаний 0.40
сохраняются. При расширении каталога можно отдельно оценить переход на приближённый
поиск; текущие семь запросов не являются полноценной оценкой качества.

Предыдущие версии точек сохраняются: это позволяет параллельному запросу со старым
снимком завершиться корректно. Автоматического удаления версий пока нет, поэтому
объём индекса со временем растёт. Их очистка потребует отдельного обслуживания;
доступ к актуальным кандидатам уже ограничен фильтрами.

Снимок результата в PostgreSQL дополнен `retrieval.vector_store`: движок, коллекции
и режим exact. Там же остаются выбранные описания, источники, оценки и версии.
Старые маршруты и их объяснения читаются без обращения к Qdrant и не переписываются.

## Ошибки и проверка

Если Qdrant недоступен или схема/ответ некорректны, семантический поиск и расчёт с
темой поиска возвращают 503 с сообщением о Qdrant. Скрытого перехода на файлы нет.
Ручное планирование без темы, история и объяснения из сохранённых фактов доступны.
Redis в этом этапе не подключён: ответы OSM и OSRM пока остаются в `data/.cache`.

```powershell
cd backend
$env:RUN_DB_TESTS='1'
$env:RUN_QDRANT_TESTS='1'
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe evaluate_retrieval.py
```

Qdrant-тесты создают коллекции с уникальным `test_travel_*` префиксом и удаляют только
собственные коллекции. Проверяются идемпотентность, обновление одного документа,
обновление метаданных без модели, фильтрация кандидатов/версий и сохранение несовместимой
схемы и параллельное первое создание коллекции. Live-набор с настоящими эмбеддингами
проверяет прежние семь русских запросов.

Дополнительно вручную проверены перезапуск контейнера и повторная индексация 13
документов с запрещённым вызовом модели: все данные сохранились. При остановленном
Qdrant поиск и семантический расчёт вернули 503; чтение сохранённого маршрута и
обычный demo-расчёт — 200. С запущенным Qdrant API создал три допустимых варианта
на сохранённый запрос; стоимость основного — 56 EUR для двух участников.

Итоговая проверка этапа: 140 тестов с `RUN_DB_TESTS=1` и `RUN_QDRANT_TESTS=1`,
Ruff, alembic check и 7/7 live-запросов прошли. Интерфейс не изменялся.
