# Компактные объяснения маршрутов

25 октября 2026. Ветка `perf/compact-llm-explanations` основана на ещё не слитой
`fix/future-trip-dates-and-mvp-verification`; реализация — `0a38b97`. Main не изменялся.

## Изменение

Раньше Qwen3-4B дословно переписывал длинные предложения из серверных фактов.
Теперь модель возвращает только `{"selected_ids":["summary","budget",...]}`.
Сервер подставляет полные сохранённые предложения и ссылки. Стоимость, посещения,
расписание, визовые предупреждения и результат валидатора от этого не меняются.

Версия композиции — `grounded-explanation-v10-fact-ids`. Сервер требует summary,
budget и limitations, а при наличии — choice, objective, visa и все source_*.
Неизвестные ID, дубликаты, пропуски и дополнительные поля отвергаются. При
невалидном ответе разрешена одна исправляющая попытка; затем используется
проверенный шаблон. При недоступности сервера шаблон доступен сразу.

Конфигурация по умолчанию:

```dotenv
LLM_TIMEOUT_SECONDS=60
LLM_EXPLANATION_TIMEOUT_SECONDS=120
```

Разбор текста сохраняет 60 секунд и 1400 токенов на попытку. Для объяснения
используются 256 токенов и оставшийся бюджет ожидания из 120 секунд, общий с
исправляющей попыткой. HTTP read timeout ограничивает ожидание данных, а не
строгое суммарное время всех сетевых фаз. Прокси Next допускает 180 секунд.
Новый параметр имеет default 120: добавлять его в существующий `.env` необязательно.
Изменение `.env` требует перезапуска backend.

Внешняя схема ExplanationOutput и формат БД сохранены. Старое объяснение возвращается
без повторной генерации; для перехода на v10 нажмите «Обновить объяснение» или
вызовите `POST /api/v1/routes/{id}/explanation?refresh=true`.

## Живое сравнение

Тот же локальный llama.cpp b11840 и Qwen3-4B Q4_K_M, ctx 4096, 24 GPU-слоя,
parallel 1, temperature 0, seed 42, thinking выключен. Intel i5-12500H,
31,7 GiB RAM, RTX 3050 Laptop. Новые модели не скачивались, платные API не вызывались.

Взяты неизменные факты предыдущей проверки: одиночный маршрут 4768 на три дня
и маршрут 4705 для шести человек на семь дней. Перед каждой серией v10 проверено
точное равенство фактов с исходными; SHA-256 включён в машинный отчёт.
Результат v9 с повышенным таймаутом снят до изменения кода. Затем выполнены три
последовательных прогона v10 на каждый случай. Тесты и другие LLM-запросы во время
серий не запускались. Прогревы не выбрасывались; состояние KV-кэша отражено в usage.

| Случай | v9: таймаут 120 с на попытку | v10: три прогона | Выходных токенов v9 → v10 |
| --- | --- | --- | --- |
| Один участник, 3 дня | 65,41 с, mode=llm | 4,82 / 2,49 / 2,77 с; все mode=llm | 794 → 36 |
| Шесть участников, 7 дней | 124,35 с суммарно; два невалидных ответа, переход на шаблон | 4,22 / 2,53 / 2,78 с; все mode=llm | 573 + 857 → 36 |

Групповой v9 не завершился по таймауту: первая попытка пропустила обязательный
факт, вторая изменила текст факта. Это показывает, почему одно увеличение
таймаута не устраняет ошибки композиции. Старый адаптер предоставлял отдельные
120 секунд каждой попытке; новый использует оставшееся время общей квоты.

Все шесть генераций v10 прошли с первой попытки, включили обязательные факты,
а paragraphs в точности равны серверным facts по selected_ids. Полнота текста
не ограничивается 256 токенами, поскольку предложения формирует сервер.

## HTTP, сохранение и источники

После завершения автоперезапуска API принудительное обновление объяснений заняло:

| Случай | HTTP-объяснение | Повторное чтение сохранённого |
| --- | ---: | ---: |
| Один участник | 3,05 с | 14,9 мс |
| Шесть участников | 3,14 с | 35,3 мс |

Оба ответа — v10, mode=llm, verified=true. Совпали исходные факты и результат
маршрута; повторный POST без refresh и GET истории вернули сохранённое объяснение.
Исходная проба во время reload отдельно сохранена: одиночный запрос ещё обработал
старый worker v9, он перешёл на шаблон через 60,27 с; групповой уже получил v10.
Эта проба не включена в таблицу скорости v10, её версия явно приведена в отчёте.

Четыре существующих синтетических fixtures дополнительно прогнаны через живую
LLM: single, food-rag, objective-visa-rag, alternative. Все четыре — mode=llm;
проверены обязательные факты, точный серверный текст и источники только посещённых
мест. Сложный случай включает восемь обязательных фактов: базовые три, выбор,
оценку, визы и два RAG-источника. Это повтор известных проверок, не независимый
новый набор для оценки качества. Новые оценки RAGAS не вычислялись.

Полный backend-набор: **737 passed, 32,42 с**, включая PostgreSQL, Redis и Qdrant.
Ruff пройден. Новые проверки охватывают ID-only схему, порядок и полноту серверного
текста, неизвестные ID, повторы, пропуски, лишний текст, старый claims-формат,
исправляющую попытку и оставшийся таймаут. Интерфейс и его сборка не менялись.

## Воспроизведение и границы

С работающими API и llama.cpp из корня проекта; ID замените на свой сохранённый
проверенный маршрут. refresh явно заменяет его прежнее объяснение:

```powershell
$routeId = 4705
$timer = [System.Diagnostics.Stopwatch]::StartNew()
$explanation = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8001/api/v1/routes/$routeId/explanation?refresh=true"
$timer.Stop()
$timer.Elapsed.TotalSeconds
$explanation | Select-Object mode, verified, prompt_version, selected_ids
```

Расширенный существующий runner с трассировкой токенов:

```powershell
.\backend\.venv\Scripts\python.exe backend/evaluate_llm.py
```

Он дополнительно запускает корпус парсера; его время нельзя смешивать с таблицей
выше. Числа и протокол этой проверки: [llm-explanation-performance.json](llm-explanation-performance.json).
Сырые локальные отчёты оставлены в `.local/evaluations/explanations-*`.

Это локальная последовательная проверка на двух маршрутах с маленьким числом
повторов, без конкурентной нагрузки. Значения не являются p95 или гарантией для
всех запросов. Проверка не повышает оценку качества парсера и не подтверждает
устойчивость свободного текста. Фактическая роль LLM остаётся ограниченной
выбором и порядком готовых фактов; числовую корректность обеспечивает планировщик.
