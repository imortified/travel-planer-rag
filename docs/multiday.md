# Многодневное планирование — первая реализация

## Контракт

`travel_date` — первая дата поездки, `end_date` — последняя, обе включены.
Ограничение: 1–14 последовательных дней. Если end_date не передана или равна
travel_date, сохраняется прежний однодневный сценарий. Старые запросы и результаты
не переписываются. Миграция `0004` добавляет nullable end_date и проверку диапазона.

`budget` — общий бюджет всей группы за весь период в евроцентах.
`start`/`end` — одинаковые ежедневные границы посещений по местному времени.
Каждый день начинается в одной и той же исходной точке (Rossio для Lisbon).
Возвращение к месту проживания, ночёвки и переезды между городами не моделируются.

Пример тела POST /api/v1/groups/{id}/trips:

```json
{
  "destination": "Demo City",
  "travel_date": "2026-10-23",
  "end_date": "2026-10-25",
  "budget": 10000,
  "start": 600,
  "end": 720,
  "mandatory": ["museum", "market", "park"]
}
```

Расчёт — прежний POST /api/v1/trips/{id}/routes?algorithm=beam.
`result.days` содержит дату, посещения, стоимость, отчёт проверки и снимок данных
каждого дня. Верхние total_cost и satisfaction относятся ко всей поездке.
Верхние visits сохранены для совместимости как объединённый список без дат;
для отображения и работы с многодневным маршрутом нужно использовать days.

## Алгоритмы и проверки

Greedy строит дни последовательно, расходуя оставшийся бюджет и исключая посещённые POI.
Beam рассматривает добавление POI и переход на следующий день как отдельные действия.
Это позволяет отложить посещение места, которое открыто в несколько дней, чтобы успеть
в другое место с более узкой доступностью. Поиск ограничен шириной луча и не гарантирует
нахождение любого существующего допустимого маршрута.

Порядок оценки: выполнение обязательных посещений и наличие маршрута, покрытие
обязательных мест, средняя накопленная полезность, минимальная полезность участника,
число дней с посещениями, меньшая максимальная нагрузка дня, стоимость, стабильный
порядок дат/времени/ID. При равной полезности beam предпочитает распределить посещения
по дням. Greedy остаётся резервным кандидатом. Не более 100 различных кандидатов за период.

Независимый validate_period проверяет расписание каждого дня по его собственным данным,
стоимость всей поездки, обязательные/запрещённые места и повторы между днями.
Обязательный POI требуется один раз за поездку, а не каждый день.
День без посещений допустим и показан явно; полностью пустая поездка невыполнима.

## Реальные данные

Расписания OSM вычисляются заново для каждой календарной даты. День с закрытыми
или недостаточно описанными местами не подменяется данными соседнего дня.
`GET /api/v1/destinations/Lisbon/pois?travel_date=2026-10-25&end_date=2026-10-27`
показывает объединённый каталог: eligible означает пригодность хотя бы в один из дней,
available_dates перечисляет такие даты. Обязательное место с пригодными данными лишь
в середине поездки поддерживается. Если данных нет за весь период, возвращается 422.

Реальный каталог по-прежнему небольшой и допускает только бесплатные POI с известными
часами работы. Поэтому заполненный маршрут на каждый день не гарантируется; увеличение
периода само по себе не создаёт новых мест. Расширение и обогащение каталога ещё требуется.
Верхний data_context — обзор каталога; для воспроизведения проверок использовать
снимки places_snapshot и travel_minutes в data_context соответствующего дня.

## Запуск и проверки

Из backend: `uv run alembic upgrade head`, затем перезапустить backend.
Frontend нужно пересобрать/перезапустить, либо использовать npm.cmd run dev.
В интерфейсе появились поля начала и конца поездки, каталог на период и карточки дней.

Из корня проекта:

```powershell
.\scripts\demo-group.ps1 -BaseUrl http://127.0.0.1:8001 -Algorithm beam -TravelDate 2026-10-23 -EndDate 2026-10-25
```

Тесты: перенос обязательного POI между днями, общий бюджет, пересчёт стоимости,
отсутствие повторов, независимый валидатор, расписание на конкретную дату,
пустой/закрытый день, непоследовательные даты, границы периода, сохранение и чтение
JSON-снимков в PostgreSQL и совместимость старого однодневного API.
