# Цены проживания через Xotelo

Этап от 25 октября 2026, ветка `feature/xotelo-lodging-quotes`, основанная на
не слитой ветке `experiment/hotel-price-provider-comparison`. Реализация — `b9c9a89`.
Предыдущий [пилот провайдеров](hotel-provider-comparison.md) сохранён отдельно.

## Использование

1. Укажите возраст или дату рождения каждого участника, город и даты поездки.
2. В блоке «Проживание · цены Xotelo» проверьте заезд, выезд и количество номеров.
3. Нажмите «Загрузить отели Xotelo», выберите объект и получите цены для группы.
   Список загружается страницами по 30 объектов; фильтр ищет только на текущей странице.
4. Можно оставить свою общую оценку проживания либо явно перенести базовую оценку
   выбранного тарифа в бюджет. Для одного номера это тариф за ночь × число ночей.
5. Постройте маршрут. История хранит выбранный отель, источник, даты получения,
   возраст участников и оценку жилья вместе с запросом поездки.

API-ключ не нужен: используются публичные `list` и `rates` из
[документации Xotelo](https://xotelo.com/), базовый URL `https://data.xotelo.com/api/`.
Поддерживаются Lisbon (`g189158`), Porto (`g189180`), Sintra (`g189164`).
Это объекты городских списков поставщика, полнота покрытия страны не заявляется.

## Что означает цена

Xotelo описывает `rate` как цену за номер за ночь. Независимое подтверждение
единицы, окончательной суммы, вместимости и доступности номера не выполнено.
В живых ответах поле налогов было `null`; оно сохраняется неизвестным, а не нулевым.
Если налог указан, он отображается отдельно без предположения о единице начисления.

Автоматический перенос доступен только для **одного номера** и только по отдельной
кнопке. В бюджет попадает базовая оценка без подтверждённых налогов и сборов.
Для нескольких номеров нельзя гарантировать, что тариф относится ко всему составу:
общая сумма автоматически не вычисляется, требуется ручная оценка всех номеров.
Ручное изменение суммы переводит её в пользовательскую оценку; отмена выбора
удаляет автоматически перенесённую сумму. При изменении дат или состава выбор сбрасывается.

Перед запросом учитывается возраст на дату заезда. Поставщик получает даты, ID отеля,
количество взрослых, детские возрасты и число номеров; имена, даты рождения и
внутренние ID участников не отправляются. Для детей 0–1 года отправляется возраст 0
по правилам Xotelo. Неизвестный возраст не заменяется взрослым; можно использовать
ручной каталог. Для запроса нужен хотя бы один взрослый.

Пустой список цен не означает отсутствие номеров или запрет размещения с детьми.
Условия питания, отмены, тип номера, детские кровати и окончательное размещение
не подтверждаются. Ссылка ведёт на страницу отеля Tripadvisor из ответа поставщика;
ссылки оформления конкретного тарифа API не предоставляет. Бронирование не выполняется.
Переезды к отелю и часы заселения/выселения пока не включены в маршрут.

## API и хранение

Примените миграции из `backend`:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Миграция `0014` создаёт `lodging_provider_quotes` в PostgreSQL. Redis хранит ответы
поставщика с TTL; PostgreSQL — наблюдения, привязанные к группе, и замороженную
историю поездки. Срок выбора цен по умолчанию 600 секунд, списка — 86400 секунд.
Настройки: `XOTELO_RATES_TTL_SECONDS`, `XOTELO_LIST_TTL_SECONDS`,
`XOTELO_TIMEOUT_SECONDS` (30 секунд). Порты остаются API 8001, интерфейс 3001.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/v1/destinations/Lisbon/xotelo-hotels?offset=0` | Страница отелей и метаданные свежести |
| POST | `/api/v1/groups/{id}/lodging-quotes` | Наблюдение цен для текущего состава группы |
| POST | `/api/v1/groups/{id}/trips` | Сохранение выбранного наблюдения в поездке |

Пример тела запроса наблюдения (ID отеля берётся из загруженной страницы):

```json
{"destination":"Lisbon","hotel_key":"g189158-d12258561","checkin":"2026-11-02","checkout":"2026-11-04","rooms":1,"list_offset":0}
```

Ответ содержит `quote_id`, `rates`, `fetched_at`, `source_timestamp`, `expires_at`,
`cache`, состав группы и статусы неопределённости. Деньги в API — целые евроценты.
Для сохранения поездки передайте `lodging_quote` вместо `lodging_plan`:

```json
{"quote_id":"UUID из ответа","rate_code":"код из rates","apply_base_estimate":true}
```

Также нужны обычные поля поездки и `budget_settings`. При `apply_base_estimate=true`
поле `budget_settings.lodging` должно точно совпасть с серверной базовой оценкой.
Сервер проверяет владельца, целостность SHA-256, срок, тариф, город, покрытие дат
и неизменность состава/возрастов. Просроченное или повреждённое наблюдение — 422,
изменившаяся во время загрузки группа — 409, недоступный источник — 503.
Это привязка к группе, а не замена будущей аутентификации пользователей.

Ключ Redis учитывает все параметры запроса, в том числе даты, номера и детские возрасты.
Попадание в кэш не обновляет исходное время получения; срок ограничен также временем
ответа поставщика. Устаревшие/неподходящие ответы не выдаются как свежие. При отказе
Redis выполняется свежий запрос; при отказе источника доступен ручной каталог OSM.
Для Xotelo выполняется одна попытка, без автоматического повтора 429.

Все три алгоритма вычитают жильё ровно один раз; базовая оценка помечается
`lodging_price_basis=xotelo_base_estimate`, а налоги и сборы остаются в
`unknown_categories`. Резерв остаётся неизрасходованными деньгами. Старый маршрут
и его пересчёт используют сохранённый снимок без повторного получения цены;
истечение тарифа запрещает новый выбор, но не удаляет историю.

## Проверки

- 673 backend-теста с PostgreSQL, Redis и Qdrant; Ruff — успешно.
- 28 frontend-тестов и производственная сборка — успешно.
- Живые списки: Lisbon 2500, Porto 1885, Sintra 187 объектов по данным поставщика;
  загружены первые 30 в каждом городе. Числа отражают ответ на дату проверки.
- Star Inn Lisbon, 2–4 ноября 2026: два взрослых, один номер — четыре тарифа;
  Agoda 116 EUR за номер за ночь по ответу Xotelo, базовая оценка двух ночей 232 EUR.
  Налоги неизвестны. Повторный запрос — Redis hit с прежними fetched/expiry.
- Четыре взрослых/два номера — три тарифа без вычисленной общей суммы;
  взрослый/ребёнок 8 лет — пустой список; неизвестный возраст — 422.
- Greedy, Beam и CP-SAT: по 16 EUR посещений + 232 EUR жилья + 50 EUR транспорта
  = 298 EUR учтённых расходов; 100 EUR резерва не добавляются к расходам.
- В интерфейсе проверены выбор, ручная корректировка, отмена автосуммы, расчёт
  трёх альтернатив и повторное открытие сохранённого проживания после перезагрузки.

Живые ответы — наблюдения, не гарантия тех же цен в будущем. Исходные ответы и
локальные технические логи сохранены в игнорируемой `.local/evaluations/`.
