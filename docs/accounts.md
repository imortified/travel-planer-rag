# Аккаунты, история и сохранённые участники

Ветка `feature/accounts-and-saved-travellers` основана на ещё не слитой
`perf/compact-llm-explanations`. Main не менялся.

## Использование

Обновите [интерфейс](http://127.0.0.1:3001/), нажмите «Нет аккаунта?
Зарегистрироваться», укажите имя, почту и пароль от 10 до 128 символов.
Регистрация сразу выполняет вход. Почта здесь служит идентификатором: письма
подтверждения не отправляются. Для участников путешествия аккаунты не требуются.

«Мои поездки» показывает последние 200 запросов аккаунта из всех его групп,
включая запросы без успешного расчёта. Открывается последний сохранённый набор
альтернатив либо одиночный результат старого формата. «Мои группы» позволяет
продолжить работу без запоминания ID; ручной ввод ID оставлен для своих групп.
«Новая группа» начинает работу с новым составом, сохраняя историю аккаунта.
После выхода личные данные убираются со страницы; повторный вход восстанавливает
группы, поездки и профили. Пароль и cookie не хранятся в localStorage.

При сохранении группы или расчёте для каждого участника сохраняется профиль:
имя, интересы, гражданство/параметры документов и возрастные данные. В новой
группе начните вводить имя: появятся до пяти подходящих профилей. Выбор копирует
данные в редактируемую форму. Одно имя само по себе не устанавливает связь:
профиль выбирается явно, можно иметь однофамильцев/тёзок и отвязать профиль.
Дата рождения переносится; возраст числом относится к прошлой поездке и очищается
для повторного ввода. Профиль обновляется при следующем сохранении группы.
Кнопка «Забыть» удаляет только профиль из адресной книги, прежние поездки остаются.

Снимок участников уже сохранённой поездки не меняется при редактировании или
удалении профиля. Состав каждой группы остаётся независимым: общий профиль не
переписывает предпочтения других ранее созданных групп. Новые группы могут иметь
свою копию данных того же человека.

## Установка и перенос прежней истории

Из папки backend:

```powershell
..\.venv\Scripts\uv.exe sync --locked --group catalog --group experiments
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m app.run --reload
```

Миграция 0016 добавляет accounts, auth_sessions, auth_rate_limits,
saved_travellers и владельца в groups/users. Старые группы, поездки, маршруты,
объяснения и снимки сохраняются. Прежние записи без владельца скрыты от обычных
аккаунтов: первый зарегистрировавшийся не получает их автоматически.

Для владельца локальной старой базы: сначала зарегистрируйте свой аккаунт в UI.
Затем в backend выполните предварительный просмотр, подставив свою почту:

```powershell
.\.venv\Scripts\python.exe -m app.accounts_legacy --email you@example.com
```

Команда показывает количество всех групп и участников без владельца. Для их
явной привязки к указанному аккаунту:

```powershell
.\.venv\Scripts\python.exe -m app.accounts_legacy --email you@example.com --apply
```

Перенос относится ко **всем** прежним записям без владельца, включая синтетические
демо и экспериментальные группы. Предполагается, что это личная локальная база.
При связях с другим аккаунтом перенос прерывается без частичного применения.
Повторный запуск не копирует уже привязанные записи. Снимки поездок не переписываются;
для адресной книги берутся последние сохранённые данные каждого прежнего участника.
Перенос не выполняется через HTTP и не запускается при регистрации. В этой рабочей
копии миграция применена, но старая история не привязана к тестовому аккаунту.

После изменения backend перезапустите API; после обновления frontend:

```powershell
cd ..\frontend
npm.cmd run build
npm.cmd run start -- --port 3001
```

Порты остались прежними: UI 3001, API 8001, docs `/docs`, health `/health`.

## API и защита данных

| Метод и путь | Назначение |
| --- | --- |
| POST `/api/v1/auth/register` | `{name,email,password}`, создать аккаунт и сессию |
| POST `/api/v1/auth/login` | `{email,password}`, войти, заменить текущую сессию |
| GET `/api/v1/auth/me` | Данные аккаунта и CSRF-токен текущей сессии |
| POST `/api/v1/auth/logout` | Отозвать текущую сессию и удалить cookie |
| GET `/api/v1/groups` | Собственные группы |
| GET `/api/v1/trips` | Последние 200 собственных запросов |
| GET `/api/v1/travellers?q=...` | Собственные профили, до 500 результатов |
| POST `/api/v1/travellers` | Сохранить профиль |
| PUT/DELETE `/api/v1/travellers/{id}` | Обновить/забыть собственный профиль |
| PUT `/api/v1/users/{id}/saved-profile` | Привязать своего участника к профилю: `{profile_id}` |

Регистрация/вход требуют `X-Auth-Request: travel-planner`. Ответ содержит
`account` и `csrf_token`; cookie `travel_session` устанавливается автоматически.
Для всех записывающих запросов личного API, включая logout, нужен
`X-CSRF-Token` из текущей сессии. Cookie нужно сохранять и отправлять вместе
с запросами. UI и Next-прокси делают это автоматически; после reload токен
восстанавливается из `/auth/me`. Поисковые фильтры профилей применяются только
после фильтра владельца.

Все пути чтения/изменения групп, участников, запросов, маршрутов, наборов
альтернатив, объяснений и групповых поисков отелей/перелётов проверяют сессию
и владельца. Чужие и скрытые старые объекты дают 404; отсутствие/истечение
сессии — 401. Недопустимый Origin, cross-site запрос или неправильный CSRF — 403.
Каталог, визовый справочник, демонстрационный расчёт и stateless LLM-разбор
остаются общими; они не читают историю аккаунта. Групповой шаринг и приглашения
в эту реализацию не входят.

Пароли хешируются Argon2id через pwdlib; в БД хранится только хеш. Сессии —
случайные 256-битные токены, в БД хранится SHA-256, срок — семь дней, logout
отзывает сессию. Cookie — HttpOnly, SameSite=Lax, без Domain. CSRF-токен связан
с конкретной сессией, передаётся в JSON/заголовке, не в URL; Origin проверяется
по точному списку. Данные авторизации не записываются в диагностические логи;
ошибки валидации auth-полей не возвращают исходный пароль. Ответы личного API
и прокси имеют Cache-Control: no-store.

Ограничения попыток в PostgreSQL сохраняются и при неудачном входе: 15 на
адрес+IP за 15 минут, 60 входов на IP за 15 минут, 10 регистраций на IP за час.
Используются фиксированные временные окна; ответ 429 содержит Retry-After.
За Next-прокси IP равен адресу прокси, поэтому IP-квота общая. Для публичного
развёртывания нужен настроенный доверенный ingress и согласованная политика
квот; произвольный X-Forwarded-For не используется.

Настройки `.env`:

```dotenv
AUTH_COOKIE_SECURE=false
AUTH_SESSION_DAYS=7
AUTH_ALLOWED_ORIGINS=["http://127.0.0.1:3001","http://localhost:3001","http://127.0.0.1:8001","http://localhost:8001"]
```

false нужен для локального HTTP. Для HTTPS-развёртывания установите true и
укажите свои точные Origin. Пользуйтесь одним адресом интерфейса: host-only
cookie для localhost и 127.0.0.1 различаются. Верификация почты, сброс/смена
пароля, MFA и отзыв всех сессий через UI пока не добавлены.

Хеширование следует [руководству FastAPI](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/);
защита запросов опирается на [рекомендации OWASP по CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).
JWT здесь не требуется: серверные сессии позволяют немедленно отозвать вход.

## Проверка

Проверены регистрация, нормализация почты, неверный пароль, дубликат, истечение,
выход/отзыв, замена cookie, Secure, CSRF/Origin, ограничение попыток, изоляция
чужих ID на разных уровнях API, неизменность снимков, удаление профиля и явный
перенос старых записей. Интеграционные тесты выполняются в откатываемых транзакциях.

В браузере выполнены регистрация отдельного синтетического аккаунта, расчёт
демо-поездки с двумя участниками, logout/login, восстановление истории и открытие
маршрута, новая группа и выбор профиля по части имени. Новые группы и аккаунт
этого UI-теста оставлены отдельно от прежних данных. Это функциональная проверка
локального MVP, не аудит безопасности публичного сервиса.

Итоговые проверки: **749 backend-тестов** (59,74 с, с PostgreSQL/Redis/Qdrant),
**32 frontend-теста**, TypeScript и production build; Ruff пройден.

Демо-скрипт теперь запрашивает вход:

```powershell
.\scripts\demo-group.ps1 -BaseUrl http://127.0.0.1:8001 -Email you@example.com
.\backend\.venv\Scripts\python.exe backend/verify_mvp.py --email you@example.com --start 2026-11-02
```

Оба инструмента запрашивают пароль локально без вывода в консоль; не передавайте
пароль в командной строке. Другие собственные HTTP-скрипты для личных путей тоже
должны выполнять вход и отправлять cookie+CSRF.
