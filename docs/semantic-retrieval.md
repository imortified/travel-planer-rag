# Эмбеддинги, поиск по интересам и RAG

Этап `feature/semantic-retrieval` основан на `feature/llama-cpp-assistant`.
Хранение векторов перенесено в Qdrant этапом `feature/qdrant-storage`, основанным
на `feature/semantic-retrieval`. [Запуск и устройство Qdrant](qdrant.md).
Ветки пока не объединены с main. Чат-модель остаётся Qwen3-4B Q4_K_M;
эмбеддинги вычисляет отдельная **Qwen3-Embedding-0.6B Q8_0** через llama.cpp b11840.

## Запуск в Windows

Из корня проекта (venv активировать необязательно):

```powershell
# Существующий runtime устанавливается scripts/setup-llama.ps1.
docker compose up -d --wait qdrant
.\scripts\setup-embeddings.ps1
.\scripts\start-embeddings.ps1
```

Вес модели — 639 150 592 байта. Загрузчик проверяет SHA256; точная ревизия и URL
закреплены в `data/embedding-runtime.json`. Веса находятся в игнорируемой `.local/`,
индекс — в Docker volume Qdrant; в Git они не попадают. Модель запускается на CPU,
порт **8082**, pooling `last`,
1024 измерения, контекст и batch 2048. Это сохраняет память RTX 3050 для чат-модели.
При желании GPU-слои задаются `-GpuLayers`, порт — `-Port` вместе с EMBEDDING_BASE_URL.

В другом терминале применить миграцию и перезапустить backend:

```powershell
cd backend
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

Для генерации объяснения запустить также `.\scripts\start-llama.ps1` из корня.
Без чат-модели показывается проверенный шаблон с теми же источниками.
Без сервера эмбеддингов доступны ползунки и обычный расчёт без темы поиска;
запрос с темой явно возвращает 503 вместо незаметного изменения поведения.
Аналогично при недоступном Qdrant возвращается 503 с отдельным сообщением.

## Сценарий интерфейса

1. Выбрать Лиссабон и даты, загрузить каталог мест.
2. В блоке «Что хочется увидеть?» написать одно положительное пожелание:
   «живопись и скульптура» или «археология и древние цивилизации».
3. Посмотреть категорию, ранжированные описания и ссылки. Выбрать участника или всех.
4. Нажать «Применить интерес и тему поиска»: вес выбранной категории станет 1,
   остальные веса сохраняются и доступны для ручной коррекции.
5. Рассчитать маршрут. В нём сохраняется снимок поиска, версии модели/корпуса,
   описания, источники и оценки близости.
6. «Объяснить выбор» добавляет до двух подходящих описаний **посещённых** мест
   к вычисленным фактам маршрута; ссылки и дата проверки видны рядом с текстом.

Добавлены три гастрономических POI с описаниями и ценой конкретного заказа
([catalog-food.md](catalog-food.md)). Недостаточная близость всё ещё требует уточнения;
наличие категории не гарантирует принятия документа. Поле общего LLM-запроса остаётся
отдельным способом заполнения формы; оно пока не извлекает произвольные фразы для
этого поиска автоматически. Тема поиска одна на поездку; веса можно применить отдельно
к разным участникам последовательными поисками.

## Устройство и ограничения

- `POST /api/v1/assistant/search`: `{text, travel_date, end_date?}`. До 300 символов,
  период 1–14 дней. Источником кандидатов служит каталог с ценами/часами/доступом,
  пригодными хотя бы для одного дня периода. Параметры дат проверяет каталог.
- Английская инструкция `Instruct: …\nQuery: …` добавляется только к запросу;
  документы кодируются без неё. Векторы проверяются на размерность, конечные числа,
  ненулевую норму и индексы, затем нормализуются. Сходство — точный cosine similarity.
- Корпус `data/semantic-knowledge.json`: четыре профиля категорий и пять описаний
  с официальными источниками, проверенными 2026-10-23. Для остальных POI используется
  только название и фактическая категория каталога. Развёрнутый профиль категории
  не выдаётся за описание отдельного музея.
- Используется Qdrant с двумя коллекциями для POI и профилей категорий, cosine,
  1024 измерения, точный поиск `exact=true`. Синхронизация проверяет отпечатки
  отдельных документов: неизменившиеся тексты не кодируются повторно, смена источника
  обновляет только payload. Поиск ограничен ID актуальных кандидатов и моделью.
  Векторы пользовательских запросов не записываются в Qdrant; применённая тема
  хранится в запросе поездки и снимке маршрута как часть истории приложения.
- Категория предлагается при cosine >= 0.55 и отрыве от второй >= 0.05.
  Неуверенный результат требует ручного выбора/уточнения. Отрицательные формулировки
  с «не», «без», «кроме» и другими явными маркерами не применяются автоматически;
  это консервативная эвристика, а не полный языковой анализ.
- Для показа описаний и RAG используется отдельный порог 0.40: короткие фразы
  и описания целых музеев имеют другую шкалу близости, чем профили категорий.
  Пороги предварительные, семь контрольных запросов не заменяют большой набор оценки.
  Оценка близости не является вероятностью и не гарантирует интерес пользователя.
- `semantic_query` — необязательное поле TripInput, миграция 0007. Для расчёта
  выбираются сначала обязательные места, затем остальные по близости, максимум 12.
  Исключённые необязательные POI не занимают эти слоты. Обязательное место не может
  исчезнуть из-за низкого cosine. Непригодные по данным POI не допускаются даже при
  высокой близости. При текущем каталоге меньше 12 мест семантическая сортировка
  обычно не меняет пул; на полезность маршрута влияют подтверждённые веса категорий.
  Сам cosine не добавляется к полезности beam/greedy, сравнение сохраняет прежний смысл.
- Бюджет, переезды, длительность, часы, обязательные/запрещённые места и отсутствие
  повторов проверяет прежний независимый валидатор. Эмбеддинги не создают новые POI,
  цены, часы работы, визовые правила или гарантии допустимости.
- RAG здесь — контролируемая композиция: LLM получает вычисленные факты и извлечённые
  описания из сохранённого снимка. Проверка требует точного текста, известных fact_id
  и обязательных фактов; ссылки присоединяет сервер. При выдуманном факте, пропуске
  источника или недоступной модели используется шаблон. Чтение старого результата
  не запускает retrieval заново и не переписывает сохранённые описания.

## Проверка

Расширенная оценка на зафиксированных 13 POI и 40 запросах, метрики ранжирования
и RAGAS описаны в [rag-evaluation.md](rag-evaluation.md). Семь запросов ниже остаются
историческим smoke-набором; его отчёт не перезаписан.

```powershell
cd backend
$env:RUN_DB_TESTS='1'
$env:RUN_QDRANT_TESTS='1'
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe evaluate_retrieval.py
```

Второй вызов использует настоящую модель и актуальный кэш OSM: семь фиксированных
русских запросов, проверки категории и присутствия ожидаемого места в top-3.
Результат — `docs/retrieval-evaluation.json`. Это небольшой smoke-набор без независимой
оценки качества; пороги нельзя считать подтверждёнными для любых формулировок.

Первый этап эмбеддингов: 124 теста, включая PostgreSQL, Ruff и alembic check; сборка
Next.js прошла. В браузере были проверены применение интереса «живопись и скульптура»,
три допустимых варианта для двух участников на 2026-10-23 и LLM-объяснение со
ссылками на два посещённых музея. Контрольная стоимость основного варианта — 56 EUR.
Проверки перехода на Qdrant описаны в [qdrant.md](qdrant.md).

Официальные инструкции: [Qwen3 Embedding GGUF](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B-GGUF),
[модель и формат инструкции](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B),
[llama.cpp server](https://github.com/ggml-org/llama.cpp/blob/b11840/tools/server/README.md).
