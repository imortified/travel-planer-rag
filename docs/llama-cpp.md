# Локальный помощник: llama.cpp и Qwen3-4B

Ветка `feature/llama-cpp-assistant` основана на `feature/route-alternatives` (b97e6a9).
По выбору пользователя используется Qwen3-4B Q4_K_M через отдельный llama-server,
без Ollama. FastAPI общается с ним по HTTP, не загружает веса и не требует CUDA SDK.
Смена модели возможна через конфигурацию и отдельный запуск подходящего GGUF.

## Зафиксированная конфигурация

- llama.cpp b11840, официальная Windows x64 сборка CUDA 12.4 и cudart;
- Qwen/Qwen3-4B-GGUF, файл Qwen3-4B-Q4_K_M.gguf, 2 497 280 256 байт;
- контекст 4096, один слот, 24 слоя на GPU, batch/ubatch 128, 8 CPU-потоков;
- генерация: temperature=0, seed=42, enable_thinking=false;
- JSON-схема передаётся в prompt и в response_format; ответ проверяет Pydantic;
- до двух запросов при невалидном ответе, один HTTP timeout 60 секунд.

Это стартовая конфигурация для i5-12500H, RTX 3050 Laptop 4 GB VRAM и около 32 GB RAM.
Размер файла не равен полной потребности в памяти. Параметры можно менять после
измерений; при нехватке VRAM уменьшить GpuLayers, включая 0 для CPU. Скорость и
побитовая воспроизводимость между устройствами/сборками не гарантируются.

Источники: [модель Qwen](https://huggingface.co/Qwen/Qwen3-4B-GGUF),
[официальный GGUF](https://huggingface.co/Qwen/Qwen3-4B-GGUF/blob/main/Qwen3-4B-Q4_K_M.gguf),
[релиз llama.cpp](https://github.com/ggml-org/llama.cpp/releases/tag/b11840),
[документация сервера](https://github.com/ggml-org/llama.cpp/blob/b11840/tools/server/README.md).
URL, размеры и SHA-256 записаны в data/llm-runtime.json. Хеши архивов взяты из
GitHub release API, модели — из LFS-метаданных официального репозитория Qwen.
Ревизия модели закреплена: bc640142c66e1fdd12af0bd68f40445458f3869b.

## Запуск в PowerShell

Из корня проекта, один раз (около 3.2 GB загрузки):

```powershell
.\scripts\setup-llama.ps1
```

Загрузчик использует возобновляемые диапазоны и проверяет SHA-256 всех файлов до
распаковки. При ошибке контрольной суммы запуск не выполняется; неверный файл нужно
удалить и скачать заново. Веса, архивы и runtime находятся в игнорируемой `.local/`.
Они не входят в Git, зависимости Python и резервную копию исходников на GitHub.

Первый терминал:

```powershell
.\scripts\start-llama.ps1
# При нехватке видеопамяти:
# .\scripts\start-llama.ps1 -GpuLayers 16
```

Сервер слушает только 127.0.0.1:8081, CORS ограничен localhost, credential CORS выключен.
Проверка готовности: http://127.0.0.1:8081/health. Скрипт работает в текущем терминале;
для остановки — Ctrl+C. Приложение не скачивает и не запускает runtime автоматически.

Второй терминал, PostgreSQL должен быть запущен:

```powershell
cd backend
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001 --reload
```

Третий терминал:

```powershell
cd frontend
npm.cmd run dev -- --port 3001
```

Конфигурация в .env: LLM_BASE_URL=http://127.0.0.1:8081,
LLM_MODEL=Qwen3-4B-Q4_K_M, LLM_TIMEOUT_SECONDS=60. Это HTTP llama.cpp, облачный
провайдер не используется. Для другой локальной модели изменить alias сервера и
LLM_MODEL вместе. Новую модель необходимо отдельно проверить на сценариях.

## Разбор текста и уточнения

`POST /api/v1/assistant/parse`: text (до 2000 символов), member_names (из текущей формы).
Возвращает draft, group_budget (евроценты), questions, warnings, model,
prompt_version и reference_date. Этот запрос ничего не записывает в БД.

Парсер извлекает направление, даты/длительность, сумму/валюту/область бюджета,
участников, общие/личные интересы, часы дня и названия обязательных/исключённых мест.
Недостающие критические поля возвращаются вопросами. Относительные даты привязаны
к текущей локальной дате backend; неоднозначный год требуется уточнить.
Период проверяется на 1–14 дней, группа — 1–6 человек. Сумму на человека умножает
сервер после проверки состава, другие валюты не пересчитываются.

Для ключевых полей модель возвращает цитаты из ввода. Поля с отсутствующим или
неподтверждённым фрагментом очищаются; неизвестные имена/названия требуют уточнения.
Это не доказывает семантическую правильность извлечения, поэтому обязателен просмотр
параметров пользователем перед применением. Команды внутри текста не исполняются,
у модели нет инструментов, доступа к SQL, файловой системе или функции расчёта.

В интерфейсе: текст → «Разобрать текст» → уточнения в том же поле → просмотр →
«Применить параметры к форме» → проверка формы → обычный расчёт. При вопросах кнопка
применения недоступна. Запрос поездки и группа создаются только обычной кнопкой расчёта.
Часы и веса, не указанные в тексте, сохраняются из формы; для нового участника
неуказанные веса равны 0.5 и показаны для проверки.

Названия сопоставляются с каталогом по точному имени/ID, уникальному вхождению или
небольшому словарю демо-имён. Неоднозначные и недоступные места нужно выбрать вручную
или явно убрать условие. Пока они не разрешены, расчёт блокируется. Состав уже
сохранённой группы не заменяется текстом; для неё принимаются только известные имена.
Неучтённые условия показываются предупреждением. Эмбеддинги и полноценное
семантическое сопоставление произвольных интересов пока не реализованы.

Если llama.cpp недоступен — 503; если два ответа не прошли проверку — 502.
Форма и символьный расчёт продолжают работать. Исходный пользовательский текст и
сырые ответы модели не записываются в логи приложения или БД.

## Проверенные объяснения

`POST /api/v1/routes/{id}/explanation` создаёт и сохраняет объяснение для проверенного
маршрута. Повторный вызов возвращает сохранённое; `?refresh=true` явно обновляет его.
Миграция 0006 добавляет nullable explanation в route_options. Старые маршруты читаются
без изменений; объяснение включается в GET /routes и GET /route-sets.

Backend строит факты по сохранённому запросу и результату: стоимость/остаток бюджета,
даты, число мест, обязательные/запрещённые места, полезность участников и сравнение
с основным вариантом. Модель выбирает и упорядочивает готовые русские предложения.
Генерация намеренно ограничена композицией этих предложений: свободный пересказ
не поддерживается. Так верификатор проверяет утверждения целиком, включая смысл,
а не только совпадение отдельных чисел или названий.

Неизвестный факт, изменённое предложение, дубликат или пропуск обязательных фактов
вызывает повторную попытку; затем используется шаблон из тех же фактов. При отказе
сервера шаблон доступен сразу. Ответ содержит mode=llm/template, model,
prompt_version, verified, facts, selected_ids, paragraphs, fallback_reason.
LLM не изменяет посещения, бюджет, часы, исходные данные или результат валидатора.

## Проверки

Из backend:

```powershell
$env:RUN_DB_TESTS='1'
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app tests alembic evaluate_llm.py ../scripts/setup_llama.py
# С работающим llama-server, отдельная реальная проверка:
.\.venv\Scripts\python.exe evaluate_llm.py
```

Автотесты используют HTTP-заглушки, включая ошибку схемы, таймаут, попытку добавить
неизвестные факты, повторную попытку, шаблон и сохранение объяснения в PostgreSQL.
Первый живой отчёт — llm-evaluation.json, семь прежних сценариев. Расширенный набор
из 30 запросов и отдельные проверки объяснений: [llm-quality.md](llm-quality.md),
отчёт `llm-quality-evaluation.json`. Скрипт теперь пишет в `.local/evaluations/`;
для публикации задаются явные `--output` и `--ragas-output`. Это acceptance-проверки,
не оценка точности на произвольных запросах.
Исправленная версия разбора `trip-extract-v2-grounded` дополнена серверными
проверками города, дат и области предпочтений: [llm-parser-grounding.md](llm-parser-grounding.md).

Сквозной сценарий через интерфейс также проверен: русский текст → просмотр →
заполнение формы → 3 варианта Lisbon на 3 дня → объяснение mode=llm, verified=true →
повторное открытие из истории. Проверенный маршрут содержит 9 мест за 78 EUR на двоих.
