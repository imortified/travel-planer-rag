## Автоматическая приёмка раздела 3.3

Новый файл `backend/tests/test_mvp_acceptance.py`: 26 запусков через HTTP, PostgreSQL,
реальные алгоритмы и валидаторы. Внешний каталог и LLM заменены контролируемыми
адаптерами; география в этих тестах синтетическая. Они проверяют интеграционные
контракты, не качество реальной модели, не актуальность тарифов и не доступность OSM.
Каждый тест откатывает свою транзакцию, включая коммиты API.

## Запуск

Из корня: запустить PostgreSQL (`docker compose up -d --wait postgres`), затем из `backend`:

```powershell
uv sync --locked
.\.venv\Scripts\python.exe -m alembic upgrade head
$env:RUN_DB_TESTS='1'
.\.venv\Scripts\python.exe -m pytest -m acceptance -q --basetemp=../.local/pytest-acceptance-new -p no:cacheprovider
```

Для всего набора дополнительно поднять Qdrant и Redis, установить `RUN_QDRANT_TESTS=1`
и `RUN_REDIS_TESTS=1`, запустить pytest без `-m acceptance`. Для каждого повторного
прогона использовать новый `--basetemp` (особенность прав временных каталогов Windows).
Из `frontend`: `npm ci`, `npm test`, `npm run build`.

## Ручные сценарии карты

Предусловия: frontend и backend запущены; для нового реального расчёта нужны OSM/OSRM
или свежий Redis-кэш. Для истории достаточно PostgreSQL. Проверять финальную production-
сборку, а не только dev-режим: worker MapLibre должен загружаться из той же сборки.

| ID | Действия | Ожидаемый результат |
| --- | --- | --- |
| B01 | Открыть сохранённый многодневный Lisbon | Только POI выбранного варианта, цвета дней, старт, пунктир; расписание и бюджет прежние |
| B02 | Выбрать второй день, затем «Все дни» | Видны соответствующие маркеры; номера дней не меняются; между разными днями нет соединений |
| B03 | Выбрать маркер, закрыть карточку, выбрать тот же POI в списке | Карточка снова открывается с названием и сохранённым временем; без дублирования карты |
| B04 | Выбрать пустой день | Сообщение об отсутствии посещений, без точек другого дня |
| B05 | Переключить вариант 2/3 | Карта обновляет набор POI и сбрасывает день/выбор; нет маркеров предыдущего варианта |
| B06 | Открыть Demo City или старый результат без географии | Негеографический список; нет выдуманных координат/карты Лиссабона |
| B07 | Включить/выключить подложку OSM | Подложка и видимая атрибуция при загрузке; сегменты и список доступны без неё |
| B08 | Недоступная подложка / WebGL | Сообщение об ограничении; список и расписание остаются. Отказ WebGL проверяется отдельно в браузере без поддержки WebGL |

Пропуск координат, нечисловые значения и несовпадение дневного/общего снимка покрыты
`frontend/tests/route-map.test.mjs`. Это проверки данных, не имитация прохождения UI.

## Фактический протокол

- Автоматически: 252 backend-теста с PostgreSQL/Qdrant/Redis и 8 frontend-тестов прошли.
  Production-сборка Next.js успешна; результаты контролируемого LLM не выдаются за живой.
- В браузере: B01–B03 и включение реальной подложки B07 проверены на ранее сохранённом
  маршруте Lisbon на 11 дней, 9 мест; выбранный второй день содержит 3 места. Проверены
  карточка маркера и повторное открытие того же места из списка.
- Прямая попытка загрузить свежий каталог на 2–4 ноября получила `OSM unavailable`.
  Новый реальный end-to-end расчёт на этих датах этим прогоном не подтверждён.
  Старый маршрут читается и отображается независимо от доступности каталога.
- B04–B06 пройдены: пустой третий день — 0 точек, альтернатива — свой набор из 6
  вместо 9 мест и сброс фильтра; Demo City — 3 посещения в списке без географии.
- Дополнительно проверено изменение бюджета, направления, дат и ID группы при уже
  открытой карте. Устранена повторная инициализация карты от несвязанных полей формы;
  доступ к слоям защищён до загрузки текущего экземпляра карты.
- Принудительный отказ WebGL/тайлов, мобильный viewport и доступность со скринридером
  в данном прогоне отдельно не воспроизводились. Обработчики предусмотрены, ручная
  приёмка этих условий остаётся открытой.

авторизация/приглашения, затем согласованный объём остальных FR. Расширение погоды,

создание 14-дневной поездки и открытие сохранённого результата после перезагрузки:
14 посещений, 7 занятых дней, 83,50 EUR, обычный темп.

## Проживание Xotelo — 25 октября 2026

[Контракт и результаты живой проверки](xotelo-lodging.md), миграция `0014`.
Этап расширяет проживание; остальные незакрытые FR/NFR выше остаются в прежнем состоянии.

| Сценарий | Проверенный результат |
| --- | --- |
| Даты, взрослые/дети, число номеров | Отдельные ключи Redis; неизвестный возраст — 422 до запроса поставщику |
| Один номер, явный выбор базовой оценки | Тариф × ночи; жильё вычитается один раз во всех трёх алгоритмах |
| Несколько номеров | Общая сумма не вычисляется; ручная оценка допустима |
| Налоги неизвестны | Не заменяются нулём, остаются в неизвестных расходах |
| Пустой семейный ответ | Показано отсутствие предложений; состав не заменён взрослыми |
| Кэш и отказ источника | Cache hit сохраняет исходные времена; устаревшие ответы не выдаются, ручной каталог доступен |
| Чужая группа, изменённый возраст, подмена суммы/тарифа | Выбор отклонён |
| Истёкший или повреждённый снимок | Новый выбор отклонён; сохранённая история и пересчёт не обновляют цену |
| Интерфейс | Выбор, перенос, ручное изменение, отмена автосуммы, расчёт и история после перезагрузки проверены |

673 backend-теста с PostgreSQL/Redis/Qdrant, 28 frontend-тестов, Ruff и сборка прошли.
Это проверка корректности обработки наблюдений, а не подтверждение финальной цены,
наличия номера, возможности размещения группы или бронирования.
