# Первая интеграция реальных данных

Этот документ описывает основу интеграции. Кураторский слой v2 добавляет платные места,
официальные исправления часов и отдельную локацию Ajuda: см. catalog-v2.md.

## Источники

- OpenStreetMap Map API: именованные node-объекты `tourism=museum|attraction|viewpoint`
  внутри небольшого прямоугольника центра Лиссабона. Ways и relations пока не включены:
  геометрический центр здания не обязательно является входом.
- OSRM Table API: направленная матрица автомобильного времени между точкой старта
  Rossio и выбранными POI. Секунды округляются вверх до минут. `null` означает отсутствие
  перехода, а не нулевое время. Это профиль driving; название параметра не превращает
  автомобильный сервер в пешеходный.
- `opening-hours-py`: вычисление открытого интервала по OSM `opening_hours` на явно
  указанную локальную дату поездки. Системная дата не используется.

OpenTripMap из первоначального ТЗ заменён адаптером OSM, не требующим ключа.
Overpass в текущем окружении возвращал отказ/таймаут, прямой Map API оказался доступен.
Границы запроса и старт фиксированы; это один демонстрационный район, а не весь город.
Результаты OSM требуют атрибуции: © OpenStreetMap contributors, ODbL 1.0.

Документация источников:

- [OSM Map API](https://wiki.openstreetmap.org/wiki/API_v0.6#Retrieving_map_data_by_bounding_box:_GET_/api/0.6/map)
- [OSRM HTTP API](https://project-osrm.org/docs/v5.24.0/api/)
- [opening-hours-py](https://pypi.org/project/opening-hours-py/)
- [OSM attribution](https://www.openstreetmap.org/copyright)

## Политика неполных данных

Без кураторского профиля в маршрутизацию допускаются POI с `fee=no` и одним непрерывным
интервалом открытия OSM на дату запроса. Для других POI профиль v2 даёт проверенную цену
и часы из указанных источников. Одного `fee=yes` недостаточно для определения тарифа.
Неизвестная цена — `null`, а не ноль.
Отсутствующие, закрытые, неразобранные или разрывные часы не заменяются выдуманным
интервалом. Ограниченный доступ и условные тарифы/доступ исключают POI.
Каталог показывает все обнаруженные точки и их `issues`/`eligible`.

Длительность 60 минут для OSM или 60–90 минут для кураторского слоя — правило планирования.
Время использует локальные минуты по Europe/Lisbon. Поддерживается период 1–14 дней;
часы работы вычисляются отдельно для каждой даты (подробнее в multiday.md).
Стоимость — только входы, транспорт/парковки/жильё не включены. Данные OSM не являются
официальной гарантией цены или расписания. Матрица OSRM описывает поездки между
привязанными к дороге координатами; время парковки и путь до двери не добавляются.

На первом этапе выбирается максимум 12 пригодных POI; обязательные места идут первыми,
остальные — по стабильному ID. Это техническое ограничение, а не поиск всех лучших
мест города. Если обязательный POI не имеет достаточных данных, API возвращает 422.

## Отказы и воспроизводимость

Файловый кеш в `data/.cache`, исключённый из Git: OSM — 24 часа, OSRM — один час.
Файлы пишутся атомарно, ключ зависит от URL и параметров. Два сетевых запроса максимум
при ошибке, таймаут подключения 5 секунд, сетевой операции — 40 секунд.
Redis пока не используется. Просроченный кеш не используется как незаметный fallback.
Недоступность источника возвращает 503; синтетические данные не подставляются, новый
результат в БД не создаётся. Для Demo City по-прежнему не нужна сеть.

Снимок каждой реальной RouteOption содержит POI, нормализованные Place, матрицу
переездов, исходные часы/fee, ссылки, даты получения и ограничения модели.
Старые результаты читаются независимо от текущей доступности API и кеша.
Таблица запросов дополнена nullable `travel_date`, миграция `0003`.

## Проверено

Живая загрузка на дату поездки 2026-10-23 дала 37 POI, из которых три прошли отбор:
Museu de Lisboa - Casa dos Bicos, Museu do Dinheiro и Museu Nacional do Desporto.
Матрица для старта и трёх мест содержит 12 направленных переходов. Beam построил
допустимый маршрут. Полный сценарий API → расчёт → сохранение в PostgreSQL → чтение
прошёл с равенством сохранённого ответа; проверочные записи откатились транзакцией.
Числа изменятся при обновлении исходных данных или даты поездки.

Автотесты используют MockTransport, не публичные API: проверяются нормализация,
даты/праздники/разрывные часы, неизвестные цены, кеш, округление, недостижимость,
некорректные матрицы, отказы источников и сохранение снимка в PostgreSQL.
