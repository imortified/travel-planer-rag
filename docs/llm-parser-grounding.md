# Проверка смысла параметров после LLM

Ветка `fix/grounded-trip-parsing` основана на `feature/llm-quality-evaluation`.
Сохранены Qwen3-4B Q4_K_M, llama.cpp, параметры генерации и порт 8081.
Версия prompt: `trip-extract-v2-grounded`. Миграция БД и изменение frontend не нужны.

## Исправления

Проверки JSON-схемы и наличия цитаты дополнены правилами для ограниченного набора
явных русских формулировок. LLM продолжает извлекать черновик. Новые правила
проверяют/уточняют поля перед показом формы; неизвестное значение требует уточнения.

| Область | Поведение |
| --- | --- |
| Город | Lisbon/Demo City должны подтверждаться своими алиасами в цитате и упоминанием в исходном тексте. Париж не превращается в Demo City. Учтены простые отрицания, включая «не в Лиссабон» |
| Год | Указанный в бюджете годоподобный номер не заменяет отсутствующий год даты. Для календарной даты нужны подтверждённые день/месяц/год; иначе появляется вопрос |
| Относительная дата | Одна явная «сегодня/завтра/послезавтра» или следующий/ближайший день недели вычисляется относительно reference_date. Несколько различных относительных дат не выбираются произвольно |
| Один день | Единственная явная дата нормализуется в начало поездки и `end_date=null`. Это работает и при ошибочном заполнении моделью только поля окончания |
| Длительность | Неуказанная длительность не добавляет дни. Явная длительность сохраняется для обычной проверки 1–14 дней и вычисления конца периода |
| Личные интересы | Категории из личных высказываний удаляются из ошибочного общего объединения. Явные положительные и отрицательные веса прикрепляются к названному участнику |
| Отрицание | Для поддержанных простых конструкций сохраняется 0, включая «не очень любим». Неуказанные категории сохраняют прежнее поведение формы |
| Неоднозначность | «Ей не нравится история», неясный субъект или конфликт значений вызывают вопрос `interests`. Кнопка применения уже блокируется при наличии вопросов |
| Имена | Используются границы слов и распространённые падежные формы известных имён. «Анна» не подтверждается словом «Жанна». Исходное написание имени не переписывается |
| Возможности | Упоминания пешего/общественного/велосипедного режима, диет и аллергенов дополнительно обнаруживаются сервером и показываются как неподдерживаемые условия |
| Уточнения | Вопросы одного поля не дублируются. Для валюты, отличной от EUR, запрашивается бюджет в EUR без лишнего запроса уже указанной иностранной суммы |

Указанные предупреждения не превращаются в выполненные ограничения. Переезды
остаются автомобильными; состав блюд/аллергены не проверяются. Визовые условия
по-прежнему обрабатываются отдельным справочником. Применение текста не создаёт
поездку автоматически, а пользователь проверяет параметры в форме.

## Границы метода

Это небольшие правила для существующей четырёхкатегорийной модели, не универсальный
анализатор русского языка. Поддержаны явные слова категорий и предикаты предпочтения,
распространённые склонения имён, простые личные/общие высказывания. Для сложного
синтаксиса, редких склонений, неявных субъектов и произвольных синонимов результат
LLM всё ещё требует проверки. Наличие цитаты и совпадение алиаса сами по себе
не доказывают понимания любого текста. Другая модель или обучение не добавлялись.

Восстановление календарной даты ограничено однозначными формами `YYYY-MM-DD`,
`DD.MM.YYYY` и «число месяц год». Невозможная одиночная дата не исправляется на
ближайшую автоматически. Для диапазонов сохраняются обычные проверки периода;
поддержка произвольных сложных дат не заявляется. Следующий/ближайший день недели
означает ближайшее такое число строго после reference_date, даже если сегодня
тот же день недели. Эта трактовка фиксирована и проверяется тестом.

## Проверки и сравнение

Исходные 30 запросов и [первый отчёт](llm-quality-evaluation.json) не изменены.
Серверные проверки отдельно прогнаны на первых структурированных ответах исходной
Qwen: все 30 теперь проходят прежние эталоны. Это **replay сохранённых ответов**,
а не новые вызовы модели и не оценка качества весов.

Дополнительно зафиксирован `data/evaluation/llm-parser-additional.json`: 12 запросов
с другим городом, отрицанием города, бюджетом 2026 EUR без года поездки, относительной
датой, переходом года, личными отрицаниями/склонениями имён, контрастом интересов,
поддерживаемым транспортом и неоднозначным местоимением. Это дополнительные
авторские регрессионные сценарии, не независимый слепой тест или случайная выборка.
Эталоны зафиксированы до окончательной оценки.

Перед окончательным прогоном выполнен предварительный development-прогон.
Он выявил заполнение единственной даты в поле окончания; после добавления проверки
границ этот прогон остановлен, его результаты оставлены в игнорируемой `.local/`.
Предварительные показатели не смешиваются с итоговыми.

Отдельные живые отчёты:

- `llm-quality-parsing-v2.json` — прежние 30 запросов на исправленном приложении.
- `llm-quality-parsing-additional.json` — 12 дополнительных формулировок.

Из `backend`, при запущенном сервере модели:

```powershell
.\.venv\Scripts\python.exe evaluate_llm.py --skip-explanations --output ../docs/llm-quality-parsing-v2.json --ragas-output ../.local/evaluations/parsing-v2-unused.jsonl
.\.venv\Scripts\python.exe evaluate_llm.py --dataset ../data/evaluation/llm-parser-additional.json --skip-explanations --output ../docs/llm-quality-parsing-additional.json --ragas-output ../.local/evaluations/parsing-additional-unused.jsonl
```

Во время живой оценки код/корпус должны оставаться неизменными. SHA-256 нового
модуля `grounding.py` добавлен в manifest измерения. Результаты относятся ко всему
пути LLM → серверные проверки; веса модели не обучались и сырые ответы могут
содержать ошибки, исправленные сервером.

Объяснения и RAGAS не изменялись. В этом прогоне они пропущены; выполняются только
разбор и прежние четыре контролируемых отказа. Пустые вспомогательные JSONL остаются
в `.local/`; исходный RAGAS-экспорт четырёх объяснений сохранён.

Часть улучшения строгого совпадения относится к нормализации однодневной поездки,
а не к опасным ошибкам. Остальные исправления подтверждают правильные параметры
в проверяемых формулировках. Это оценка приложения после серверной обработки;
сырые ответы той же модели могут оставаться ошибочными.

Итоговый отчёт завершён с `inputs_unchanged=true`. Во время оценки не было намеренной
параллельной LLM-нагрузки; сравнение времени одного прогона не контролирует температуру,
частоты оборудования и кэш префикса. Рост времени следует отдельно проверить повторными
замерами; NFR полного планирования эта таблица не закрывает.

Первый живой прогон дополнительных формулировок: **8/12**. Все 12 направлений и
бюджетов обработаны согласно проверяемым полям. Два отклонения — уточнения на
неподдерживаемых направлениях: потеря цитаты даты в запросе о Риме и лишний вопрос
об обязательных местах при отрицании города. В двух других случаях выявлены
неупомянутый общий вес `food=0` и ошибочная маркировка автомобиля как неподдерживаемого.
Этот отчёт сохранён для анализа следующей точечной правки.
