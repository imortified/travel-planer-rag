# Воспроизводимая оценка локального помощника

Ветка `feature/llm-quality-evaluation` основана на `feature/lisbon-food-catalog`.
Этот файл фиксирует исходную оценку. Исправления и новые отчёты описаны отдельно
в [llm-parser-grounding.md](llm-parser-grounding.md); baseline ниже не переписан.
Выбранные модели сохранены: Qwen3-4B Q4_K_M для текста и Qwen3-Embedding-0.6B Q8_0
для поиска. Генератор работает через установленный llama.cpp b11840, порт 8081.

Старый отчёт `llm-evaluation.json` сохраняет первый прогон семи сценариев от 23 октября.
Новая процедура расширяет проверку до 30 русских запросов, четырёх объяснений и
четырёх контролируемых отказов. Внешние каталоги/БД, Redis и Qdrant этому прогону
не требуются. Данные объяснений синтетические, с зафиксированными сведениями о POI.

## Запуск

В одном терминале из корня:

```powershell
.\scripts\start-llama.ps1
```

В другом из `backend`:

```powershell
.\.venv\Scripts\python.exe evaluate_llm.py
# Отдельный случай и повторные наблюдения разбора:
.\.venv\Scripts\python.exe evaluate_llm.py --case negative-interest --repeat 3
```

По умолчанию отчёт и экспорт контекстов находятся в игнорируемой
`.local/evaluations/`. Публикация проверочного отчёта с публичными вымышленными
данными выполняется явно:

```powershell
.\.venv\Scripts\python.exe evaluate_llm.py --output ../docs/llm-quality-evaluation.json --ragas-output ../docs/llm-quality-ragas.jsonl
```

`--dataset` задаёт собственный JSON той же структуры; `--skip-explanations` оставляет
только разбор и контролируемые отказы. `--repeat 1..5` повторяет запросы разбора;
четыре объяснения выполняются один раз. Имена случаев/пути проверок проверяются до
вызовов модели. Обычный backend и записи пользователей не изменяются.

Отчёт атомарно сохраняется после каждого случая с `completed=false`. Только полный
прогон имеет `completed=true`. Код завершения 1 означает несовпадение эталона,
непройденную защитную проверку либо изменение измеряемых файлов во время прогона;
это не потеря частичного отчёта. Доля объяснений `mode=llm` измеряется отдельно:
код завершения проверяет достоверность возвращённого объяснения, включая шаблон.

## Что измеряется

Набор `data/evaluation/llm-parser.json` имеет версию, фиксированную опорную дату
24 октября 2026 и вручную заданные эталоны. Входы составлены до первого прогона.
Они покрывают числа/валюту/область бюджета, дробные суммы и нулевой бюджет,
явные/относительные даты, состав группы, имена, общий/индивидуальный интерес,
отрицание, часы, обязательные/исключённые места, конфликт условий и команду внутри
текста. Отдельно проверяются неполный ввод и неподдерживаемые город/транспорт/диета.

Для каждого сценария явно задано, какие поля проверяются. Неуказанные в эталоне
поля не оцениваются; это не проверка всех полей всех ответов. Условия мест
сравниваются без учёта регистра/порядка, имена участников сохраняют точное написание.
`effective_count` учитывает имена в тексте и текущий состав формы. Разрешённые и
обязательные уточнения заданы отдельно: лишний вопрос может провалить строгий случай.

Метрики:

- Полное прохождение случая и точность каждого проверяемого поля после серверной
  проверки/нормализации. Это качество всего пути разбора, не сырой модели отдельно.
- Корректность JSON-схемы первого и любого полученного ответа, число repair.
  Сырой структурированный ответ сохраняется для анализа отличий от итогового draft.
- Ошибки/таймауты входят в знаменатели и проваливают проверки, включая ожидаемые
  `null`; отсутствие ответа не считается корректным отсутствием поля.
- Время разбора: медиана, p95 по ближайшему рангу и максимум, отдельно по всем
  попыткам и по запросам без исключения. Сюда входят инференс, repair и валидация.
- Для объяснений: точное соответствие сохранённым фактам, обязательные бюджет/
  ограничения/оценка/визы/источники, ссылки только на посещённые места, доля LLM
  и доля template. Успешный шаблон подтверждает защиту, а не качество генерации.
- Контролируемые отказы: таймаут → 503, два невалидных JSON → 502, ручной demo-расчёт
  остаётся доступным; недоступная модель/выдуманный факт → проверенный шаблон.
  Это искусственные неисправности через HTTP-заглушку, не реальные сбои сервера.

Сохраняются запрошенная/возвращённая модель, параметры генерации, длительности,
версия prompt, SHA-256 корпуса/кода/описаний и Git revision перед прогоном.
Версия runtime и checksum весов берутся из установочного манифеста, а не измеряются
заново. Пользовательские тексты и сырые ответы не добавлены в production-логи;
полные ответы находятся только в явно создаваемом benchmark-отчёте.

## Где полезен RAGAS

[RAGAS](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/) содержит
метрики поиска, соответствия ответа вопросу и опоры на контекст. Для этого проекта
полезны [Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)
и [Context Precision](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/)
вместе с Context Recall. Набор контекстов, ответ, вопрос и при необходимости эталон
позволяют отдельно оценивать извлечение и формирование ответа.

Числа, даты и бюджет проверяются точными эталонами. Мягкое семантическое сходство
не подтверждает правильность 300 EUR на группу при ошибочном результате 900 EUR.
Ограничения маршрута по-прежнему проверяет независимый валидатор планирования.

Подготовлен **экспорт для дополнительной оценки**, библиотека RAGAS не добавлена
в зависимости и RAGAS-score не вычислялся. JSONL содержит оболочку с `case_id`,
`mode` и `sample`: `user_input`, `response`, `retrieved_contexts`. Все факты, которые
видел генератор, включены в контекст, в том числе вычисленные бюджет/оценка/визы.
Передача только описаний кафе ошибочно посчитала бы остальные обоснованные факты
галлюцинациями. Метаданные оболочки не передаются в аргументы метрики.

Пример чтения для актуального collections API RAGAS после выбора и настройки судьи:

```python
import json
from pathlib import Path
from ragas.metrics.collections import Faithfulness

rows = [json.loads(line) for line in Path("docs/llm-quality-ragas.jsonl").read_text("utf-8").splitlines()]

async def score(evaluator_llm):  # отдельно настроенный и проверенный судья
    metric = Faithfulness(llm=evaluator_llm)
    for row in rows:
        result = await metric.ascore(**row["sample"])
        print(row["case_id"], row["mode"], result.value)
```

Здесь экспортируется проверка объяснения по **синтетическому сохранённому контексту**.
Она не измеряет полноту живого каталога, правильность цен, качество Qdrant или
правдоподобие причин алгоритмического выбора. Для Context Precision/Recall нужен
отдельно размеченный набор вопросов и релевантных документов/эталонов.

Рекомендуемый следующий шаг для RAGAS — выбрать независимого судью, проверить его
на небольшом вручную размеченном наборе и сохранить модель/версию/параметры судьи.
Самооценка той же Qwen3-4B остаётся вспомогательным сигналом. Это методологическое
ограничение, не запрет RAGAS; новая модель или облачный API в этом этапе не выбирались.

## Как трактовать результат

Первый полный разбор корпуса: **19/30** строгих сценариев (63,3%), бюджет **30/30**,
JSON-схема с первой попытки **30/30**, исключений и repair нет. Медиана **12,763 с**,
p95 **14,756 с**, максимум **16,840 с**. Это последовательные запросы к локальной
Qwen3-4B Q4_K_M с уже загруженными весами; первая генерация включена в замер.

| Наблюдение | Случаи | Значение |
| --- | --- | --- |
| Общие и индивидуальные интересы смешаны | `individual-interests` | Личные веса сохранены, но добавлены общие history/nature; при заполнении формы они распространяются на всех |
| Потерян нулевой вес | `negative-interest` | «Историю не любим» пропущено; положительный интерес к природе сохранён |
| Предположен год | `missing-year` | Модель подставила 2026 вместо уточнения |
| Неподдерживаемый город заменён | `unsupported-city` | Париж превратился в Demo City; проверка наличия цитаты не доказывает соответствия значения цитате |
| Потеряно неподдерживаемое условие | `walking-request`, `diet-request` | Модель не внесла пеший режим/веганские блюда в unsupported |
| Не разрешена относительная дата | `next-monday` | Вместо 26 октября возвращён вопрос; безопасное, но менее полезное поведение |
| Лишний вопрос | `unsupported-currency` | Помимо запроса EUR модель попросила бюджет; строгий эталон разрешал только валюту |
| Эквивалентная запись одного дня | `zero-budget`, `exact-place-names`, `walking-request`, `conflicting-places` | Конец равен началу вместо null; это не изменение длительности поездки |

Один случай может иметь несколько отклонений. Строки таблицы не складываются в
независимые частоты. Приоритет исправлений — подтверждение города/даты по тексту,
сохранение отрицательных и персональных интересов, затем неподдерживаемые условия.
Промпт, серверная логика и эталоны во время измерения не менялись.

Четыре объяснения: **3 LLM + 1 template**, все четыре возвращённых результата
соответствуют фактам. В `objective-visa-rag` первая генерация пропустила `objective`
и `visa`, repair пропустил `source_2`. Предложения из выбранных фактов не изменялись,
но обязательная полнота не соблюдена. После двух ответов с корректной JSON-схемой
сработал шаблон. Времена случаев: 27,753; 31,913; 76,828; 25,275 с. Максимум/p95
четырёх наблюдений равен 76,828 с; это слишком маленькая выборка для общего вывода
о производительности объяснений.

Этот пример показывает границу Faithfulness: опора всех высказанных утверждений
на контекст сама по себе не требует упомянуть все обязательные сведения.
Точная проверка наличия бюджета/визы/источника нужна дополнительно.

Все **4 контролируемых отказа** прошли; проверены **318 backend-тестов** с
PostgreSQL, Redis и Qdrant, Ruff и форматирование. Изменений frontend, алгоритмов,
production-промптов или модели в этом этапе нет. JSON-отчёт завершён, содержит
`inputs_unchanged=true`; RAGAS-экспорт содержит четыре образца, оценок судьи нет.

Это небольшой acceptance-набор, не случайная выборка пользователей и не доказательство
общей точности модели. Один прогон не измеряет устойчивость; `temperature=0` и seed
не гарантируют идентичность на другом оборудовании. Показатели времени не закрывают
NFR для полного группового планирования с источниками и несколькими днями.

Строгий эталон может отмечать функционально эквивалентные представления, например
`end_date=null` и дату окончания, равную началу однодневной поездки. Лишний безопасный
вопрос тоже считается отклонением, но не означает неправильную сумму или опасную
генерацию. Отчёт хранит каждое несовпадение; эталоны после наблюдения результата
не переписаны ради повышения процента.

Для улучшений следует сохранить этот baseline, выделить отдельные development и
проверочные наборы и сравнивать версии на одинаковых условиях. Защитный шаблон,
качество LLM и качество поиска нельзя объединять в одну цифру «RAG работает».
