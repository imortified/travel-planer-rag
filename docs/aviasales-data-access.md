# Aviasales Data API: проверка доступа

25 октября 2026 доступ подтверждён живыми запросами: HTTP 200 и `success=true`.
Отдельная активация или заявка в поддержку для проверенного метода не потребовалась.
Ветка `experiment/aviasales-data-access` основана на ещё не слитой
`feature/xotelo-lodging-quotes`. Это отдельный пилот доступа перед интеграцией перелётов.

## Подключение

По [условиям доступа](https://support.travelpayouts.com/hc/en-us/articles/203956083-Requirements-for-Aviasales-data-API-access)
для Data API нужен токен из профиля Travelpayouts. Согласно
[списку API партнёров](https://support.travelpayouts.com/hc/en-us/articles/20384016664594-Brands-that-provide-access-to-APIs-and-data-feeds-for-Travelpayouts-partners),
отдельное одобрение бренда для Data API не требуется. Общий FAQ также упоминает
подключение программы Aviasales; для нашего токена доступ к данным уже работает.
Статус участия аккаунта в партнёрской программе и атрибуция продаж этим пилотом не проверяются.

В корневом локальном `.env` задан `TRAVELPAYOUTS_API_TOKEN`. `.env` игнорируется Git;
в `.env.example` оставлено пустое поле. Токен не передаётся во frontend, URL или отчёт.
Запрос идёт по HTTPS на фиксированный endpoint
`https://api.travelpayouts.com/aviasales/v3/prices_for_dates`, токен — в
заголовке `X-Access-Token`. Перенаправления отключены.

Команда из корня проекта:

```powershell
.\backend\.venv\Scripts\python.exe .\backend\check_aviasales.py --origin WAW --destination LIS --departure 2026-11-15
```

Туда-обратно:

```powershell
.\backend\.venv\Scripts\python.exe .\backend\check_aviasales.py --origin WAW --destination LIS --departure 2026-11-15 --return-date 2026-11-22
```

Нужны трёхбуквенные IATA-коды. Валюта пилота — EUR, рынок по умолчанию `ru`;
для проверки другого кэша поддерживается `--market us`. Один запуск делает один
запрос, возвращает до пяти записей, не повторяет 429 и не оформляет бронирований.
Пустая выдача отличается от ошибки доступа. Даты примеров нужно заменить, когда они пройдут.

## Живые результаты

Вылет 15 ноября 2026, рынок `ru`, проверено 25 октября 2026:

| Направление | Результат Data API |
| --- | --- |
| Варшава WAW → Лиссабон LIS | 1 запись, 81 EUR |
| Варшава WAW → Порту OPO | 1 запись, 67 EUR |
| Вильнюс VNO → Лиссабон LIS | 1 запись, 96 EUR |
| Минск MSQ → Лиссабон LIS | Успешный ответ, пустая выдача |
| Варшава → Лиссабон, возврат 22 ноября | 5 записей, 165–198 EUR |

[Машинный отчёт без токена](aviasales-data-pilot.json) содержит параметры,
HTTP-статусы, время нашей проверки и разрешённые поля ответа поставщика.

Это **накопленные наблюдения цен**, а не подтверждённые предложения для нашей группы.
Время нашей проверки не означает, что цена впервые найдена в этот момент.
По [документации метода](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API)
данные берутся из кэша предыдущих поисков; состав пассажиров в этом методе не задаётся.
Нельзя автоматически назначать детские скидки, умножать цену на группу и обещать
наличие билетов, багаж, окончательные условия или полноту всех сегментов.
Пустой кэш по Минску не доказывает отсутствия перелётов.

## Проверки и следующий этап

Семь изолированных тестов проверяют передачу токена только в заголовке,
исключение секретов/посторонних полей из вывода, различие пустой выдачи и ошибок,
валюту и отсутствие повторного запроса на 429. Ruff прошёл. Пять живых случаев выше
и запуск CLI из корня проверены отдельно; PostgreSQL, Redis, маршруты и UI не меняются.

Следующий этап — форма аэропортов/дат, просмотр наблюдений с переходом на поиск,
проверка сегментов и времени прилёта/вылета, отдельная общая оценка транспорта,
TTL-кэш и замороженная история. Перелёт и трансфер нужно учитывать раздельно,
чтобы не списывать транспорт дважды. Перед автоматическим изменением дневного
расписания потребуется проверить часовые пояса и полноту информации о пересадках.
