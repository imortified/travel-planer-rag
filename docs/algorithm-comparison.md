# Сравнение greedy и beam search

Проверяется шесть фиксированных синтетических сценариев из `planning/scenarios.py`.
Два участника, один день, максимум три POI. Beam width = 32. В beam включён результат
greedy как кандидат. Это сравнение greedy с beam, использующим greedy как резерв,
а не с полностью независимым вариантом поиска.

Оба результата проверяются одним независимым валидатором.
В текущем запуске применяется `normalized-group-objective-v1` (objective-function.md),
одинаковая формула для обоих методов. Это повторный прогон прежних контрольных случаев.

| Сценарий | Greedy: выполнимость / полезность | Beam: выполнимость / полезность |
| --- | --- | --- |
| Узкие окна обязательных мест | Нет / — | Да / 1.8 |
| Узкие окна необязательных мест | Да / 1.0 | Да / 1.8 |
| Один дорогой объект против двух доступных | Да / 1.0 | Да / 1.6 |
| Обязательное место запрещено | Нет / — | Нет / — |
| Нет данных переездов | Нет / — | Нет / — |
| Пустой каталог | Нет / — | Нет / — |

В первом сценарии greedy сначала выбирает место с открытием в 11:00 и посещает его
до 12:00. Второе обязательное место закрывается в 10:00. Beam сохраняет вариант
сначала посетить раннее место, затем позднее, и выполняет оба требования.

Полезность — средняя по участникам сумма весов посещённых категорий, без нормировки
на число посещений. В новом JSON для невыполнимых маршрутов полезность и F равны null;
частичные маршруты остаются диагностикой.

| Допустимый случай | Greedy F | Beam F |
| --- | --- | --- |
| Узкие окна обязательных мест | — | 1,0000 |
| Узкие окна необязательных мест | 0,5556 | 1,0000 |
| Один дорогой объект против двух доступных | 0,2346 | 0,4654 |

Скрипт `backend/compare_algorithms.py` выполняет по 20 повторов расчёта каждого
алгоритма, включая финальную валидацию, и сохраняет медиану времени в миллисекундах,
порядок посещений, стоимость, полезность, F, минуты переездов, версию критерия и
выполнимость в JSON рядом с этим файлом.
БД, HTTP, загрузка данных и LLM в измерение не входят. Время зависит от компьютера;
эти маленькие случаи не позволяют делать выводы о производительности на реальных городах.

Тесты дополнительно сравнивают beam с полным перебором маленького сценария,
проверяют воспроизводимость при перестановке входных POI и ограничения API.
Сценарии специально выявляют слабые места greedy; они не являются независимой
репрезентативной выборкой. Для дипломного эксперимента нужен отдельный расширенный
набор с большим числом POI, конфликтующими интересами и разными значениями ширины луча.
