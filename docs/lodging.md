# Поиск и выбор проживания

Этап `feature/lodging-search-and-selection` основан на незамерженной ветке
`feature/age-aware-ticket-pricing` (`e88d1ce`). Сервер, каталог и форма впервые
проверены и сохранены в `bb28c9e`. Миграция `0013` применена локально.

## Что доступно

Для Lisbon, Porto и Sintra с окрестностями добавлен поиск объектов размещения:
отелей, хостелов, гостевых домов, апартаментов и мотелей. Источник — существующий
PBF Португалии Geofabrik/OpenStreetMap, состояние 23 октября 2026, 20:20:51 UTC.
Извлечены именованные узлы и контуры в исследовательских прямоугольниках проекта.
Это справочник объектов, а не выдача свободных номеров на даты.

| Каталог | Записи всех типов | С тегом hotel |
| --- | ---: | ---: |
| Lisbon | 683 | 375 |
| Porto | 552 | 202 |
| Sintra | 82 | 35 |

Всего 1317 записей каталогов, 1313 различных OSM ID: области Lisbon/Sintra частично
пересекаются. Имеются 555 ссылок на сайты из OSM; они не объявляются независимо
проверенными официальными страницами. Сайты могут отсутствовать или устареть.
Поиск нормализует регистр и диакритику, фильтрует имя/адрес и тип, поддерживает
пагинацию. Список не ранжируется по цене и не заявляет полноту покрытия.
Классификация, адрес и координаты взяты из OSM; центр контура не является входом.
Дубли разных OSM ID и ошибки классификации возможны.

В форме можно указать заезд, выезд и 1–6 номеров на группу, выбрать объект и
перейти на его сайт для проверки условий. Выбор включает бюджет всей поездки.
Пользователь вводит **одну общую оценку жилья за все ночи, номера и участников**
в существующее поле расходов. Сумма не умножается повторно ни на ночи, ни на людей.
Пустая сумма сохраняется как неизвестная, а не как бесплатное проживание.
Изменение дат, номеров или состава сбрасывает выбор; оценку нужно перепроверить.

Дата выезда должна следовать за заездом, длительность — 1–30 ночей. Проживание
покрывает календарные даты поездки: заезд не позже первого дня, выезд не раньше
последнего. Для двух дней допустима одна ночь. Фактическое время выселения,
хранение багажа и возможность доступа в номер в последний день не моделируются.

## Цены и доступ к внешним API

Проверка провайдеров проведена **25 октября 2026**:

- На [официальном сайте Amadeus](https://developers.amadeus.com/) объявлено,
  что Self-Service portal закрыт 17 июля; сейчас сайт предлагает Enterprise APIs
  с доступом по запросу. Старые страницы Self-Service с бесплатными квотами
  продолжают индексироваться. [Официальный репозиторий спецификаций](https://github.com/amadeus4dev/amadeus-open-api-specification)
  архивирован владельцем 17 июля 2026. Новый адаптер старого Self-Service не добавлен.
- [Tripadvisor Content API](https://www.tripadvisor.com/business/solutions/hotels/content-api)
  предоставляет контент, первые 5000 вызовов в месяц бесплатны, но подключение
  требует карты и предполагает оплату превышения. Для цен бронирования предусмотрен
  отдельный Hotel Pricing API с доступом по запросу. Content API не подключён
  и не используется как источник цен проживания.
- [Booking.com Demand API](https://developers.booking.com/demand/docs/getting-started/prerequisites)
  требует статуса Managed Affiliate Partner, договора, API token и Affiliate ID.
  Пользовательского доступа к этому API в данном этапе нет.

Никакие платные подписки и аккаунты не создавались. В текущей реализации нет
запросов предложений к перечисленным поставщикам, тестовых цен, подменённых под
реальные, или автоматического оформления бронирования. Ссылки ведут на сайт
из каталога, не на гарантированное предложение с предзаполненными датами.

Статусы сохраняются явно: `mode=directory`, `price_status=user_estimate|unknown`,
`availability_status=not_checked`, `occupancy_status=not_checked`,
`booking_status=not_booked`. Для перехода к реальным предложениям нужен отдельный
доступный поставщик цен и его проверенный договор API.

## Хранение и API

`lodging_catalog_versions` хранит неизменяемые снимки публичного каталога PostgreSQL
с SHA-256, исходной датой и атрибуцией; `lodging_catalog_heads` указывает текущую
версию города. Публикация атомарна, блокирует указатель города, переиспользует
одинаковый снимок и отвергает более старый источник. Ошибка публикации не стирает
предыдущую версию. Контрольная сумма проверяется при чтении. Каталог не хранится
в Redis или Qdrant: он не содержит цен, а семантический поиск жилья пока не добавлен.

`GET /api/v1/destinations/{city}/lodgings?q=&kind=hotel&page=1&page_size=20`
возвращает публичные записи, версию, исходную дату и явные статусы неизвестной цены
и непроверенного наличия. Отсутствующий/повреждённый каталог возвращает 503,
без подстановки выдуманных отелей. Ограничения страницы: размер 1–50, номер 1–500.

`POST /api/v1/groups/{group_id}/trips` принимает необязательный `lodging_plan`:

```json
{
  "property_id": "osm:node:5096400091",
  "catalog_version_id": 1,
  "checkin": "2026-10-27",
  "checkout": "2026-10-28",
  "rooms": 2
}
```

ID версии относится к конкретной локальной БД. Запрос требует полного бюджета
`budget_settings`; общая оценка берётся из `budget_settings.lodging`.
Названия, ссылки и координаты клиент не задаёт: сервер загружает их из указанной
проверенной версии и отвергает объект/версию другого города или отсутствующий ID.
В `trip_requests.lodging_snapshot` замораживаются объект, версия/хеш, даты, комнаты,
возраста на заезд и исходная общая оценка. Старый выбор не зависит от текущего каталога.

Известные возраста 0–17 сохраняются отдельно от взрослых 18+, неизвестные — отдельно.
Это описание группы, а не подтверждение политики конкретного отеля. Детские скидки,
бесплатные кровати, дополнительные места и соответствие вместимости не выводятся
из возраста. Имена и даты рождения не отправляются внешним сервисам. Возраст из
даты рождения считается на заезд; ручной возраст остаётся заявленным пользователем.

Greedy, Beam и CP-SAT используют прежний общий бюджет после однократного вычета
жилья/транспорта/резерва. Выбор жилья пока не меняет центральную точку старта,
матрицы расстояний или расписание заселения. Переезд к/от отеля и перелёты не добавлены.
Наличие отеля в результате не означает наличие номера или соответствие группы правилам.

## Проверки и воспроизведение

628 backend-тестов с PostgreSQL, Redis и Qdrant, 27 frontend-тестов, Ruff и
production-сборка прошли. На живом REST API прошли девять двухдневных расчётов:
три города × Greedy/Beam/CP-SAT. Дополнительно проверены неизвестная цена и возраст,
неизменность истории, отбрасывание подменённых ID и отсутствие повторного списания.
В браузере проверены поиск по названию, выбор, сброс при изменении номеров,
создание поездки и повторное открытие после перезагрузки страницы.
Машинный отчёт — [lodging.json](lodging.json).

```powershell
cd backend
.\.venv\Scripts\python.exe -m alembic upgrade head
# osmium доступен после установки опциональной группы catalog.
.\.venv\Scripts\python.exe extract_lodging.py --input ../.local/downloads/portugal-latest.osm.pbf --output ../.local/evaluations/portugal-lodgings.json
.\.venv\Scripts\python.exe refresh_lodging.py --extract ../.local/evaluations/portugal-lodgings.json
```

PBF и извлечённый JSON остаются в игнорируемой `.local`; снимки публикуются в БД.
Для воспроизведения нужен собственный локальный PBF с исходной датой в заголовке;
не следует сбрасывать его дату скачивания. Порты прежние: UI `3001`, API `8001`.
Этот этап закрывает каталог и сохранение выбора проживания, **не поиск актуальных
цен и доступных номеров**. Полный MVP по исходному ТЗ пока не заявляется.
