# Попутно — интерфейс MVP

Next.js App Router, React и TypeScript. Стили локальные, без внешних шрифтов и CDN.
Проверено на Node.js 22.15.0. Версии зависимостей фиксирует package-lock.json.

Текстовый ввод и объяснения используют локальную Qwen3-4B через llama.cpp.
Сначала из корня запустить scripts/start-llama.ps1; установка и ограничения:
[llama-cpp.md](../docs/llama-cpp.md). Для сохранения объяснений нужна миграция 0006.
При недоступности модели обычная форма доступна, объяснения используют шаблон.

## Запуск

Сначала PostgreSQL и backend из корня проекта:

```powershell
docker compose up -d --wait
cd backend
.\.venv\Scripts\alembic.exe upgrade head
.\.venv\Scripts\python.exe -m app.run --reload
```

В отдельном терминале:

```powershell
cd D:\Diplom\travel-planer-rag\frontend
npm.cmd ci
npm.cmd run dev -- --port 3001
```

Открыть http://127.0.0.1:3001. `npm.cmd` работает и при запрете ps1 в PowerShell.
При занятом порте остановить лишнюю копию приложения.

Запросы идут через Next.js на backend, CORS не требуется. По умолчанию backend —
http://127.0.0.1:8001. Для изменения скопировать `.env.example` в `.env.local`,
изменить API_BASE_URL и перезапустить Next.js.
Прокси сохраняет `X-Request-ID` между браузером и backend. Ошибки API показывают
код запроса, по которому можно найти события в JSON-логах ([logging.md](../docs/logging.md)).

## Сценарий

Третий алгоритм — **CP-SAT · OR-Tools**. Можно задать общий лимит набора 0,05–30 с.
Отчёт показывает OPTIMAL/FEASIBLE/INFEASIBLE/UNKNOWN и границы масштабированной
оценки; UNKNOWN не означает невозможность. Описание: [cp-sat.md](../docs/cp-sat.md).

Новые расчёты используют [общую целевую функцию](../docs/objective-function.md).
В сравнении показаны оценка F, минуты переездов и разрыв покрытия интересов.
В блоке «Оценка маршрута» можно раскрыть формулу, вклады и нормировку.
Коэффициенты исходные; F не является процентом удовлетворённости или гарантией оптимума.
Старые маршруты открываются без пересчёта и без нового отчёта.

1. Назвать группу, ввести от одного до шести участников и выставить интересы.
   Для Португалии раскрыть «Гражданство и документы» у участников.
2. Выбрать направление, начало и конец поездки (1–14 дней), общий бюджет, время дня и алгоритм.
3. При необходимости заранее загрузить каталог на период кнопкой «Загрузить места на период»
   и выбрать обязательные и исключённые места. Для просмотра каталога нужна дата начала.
   Выбрать цель въезда; «Проверить визовые условия» покажет предварительный отчёт без сохранения.
4. Построить маршрут: каталог выбранного города и периода загрузится автоматически,
   в том числе после изменения дат. Затем группа, запрос и набор из 0–3 допустимых
   вариантов сохраняются в PostgreSQL. Ошибка загрузки каталога останавливает расчёт
   с сообщением; кнопки становятся доступны для повторной попытки.
5. Сравнить стоимость, полезность участников и баланс. Выбрать столбец для просмотра
   расписания по дням и независимого отчёта проверки; раскрыть отличия по местам.

Нужна миграция **0008**. [Визовый справочник](../docs/visa-rules.md) охватывает
Португалию и семь гражданств. Бюджет и расписание проверяются отдельно от документов:
визовое предупреждение не блокирует построение плана. Отчёт показывает источники,
дату проверки и срок пересмотра данных; действительность виз и паспортов не проверяется.
Изменение документов скрывает прежний предварительный отчёт. Сохранённый маршрут
показывает собственный снимок профилей и правил, даже после изменения группы.

Нужна миграция 0005. Подробности алгоритма и API: [alternatives.md](../docs/alternatives.md).
Если найдено меньше трёх разных вариантов, интерфейс это сообщает. При отсутствии
допустимых вариантов выводится диагностика. Выбор столбца не изменяет сохранённый набор.

Без даты окончания создаётся однодневный запрос. Дни без посещений показаны явно.
Расширение каталога ещё требуется: длительный период не гарантирует наличие мест на каждый день.

Группу можно отдельно сохранить и загрузить по ID. Последний ID запоминается в браузере.
История показывает запросы группы и открывает последний расчёт каждого со всеми
вариантами. Старые одиночные результаты продолжают открываться.
Результат отображает сохранённый снимок участников, а не текущие ползунки.
После ошибки расчёта повторная попытка с теми же параметрами использует уже созданный
в этой сессии TripRequest.

Сохранённые имена и название группы пока не редактируются: backend не поддерживает
эти операции. Удаление сохранённых участников, авторизация, карта и редактирование
готового маршрута в эту итерацию не входят. Это локальное приложение.
В реальном каталоге есть бесплатные места и проверенные обычные взрослые тарифы;
категории history, nature, art. Цены, источники и даты проверки показаны в каталоге.
Переезды автомобильные, транспортные расходы не включены в стоимость входов.

## Проверки

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run start
```

Перед production-сборкой остановить `next dev`: они используют одну `.next`.
Сборка не требует API или БД; расчёт требует обоих сервисов.
Ручные сценарии: пустые имена, создание группы и демо-маршрута, каталог по дате,
расчёт Lisbon, история, загрузка группы по ID.
Для LLM: разбор текста, уточнение бюджета, просмотр и применение параметров,
сопоставление названий мест, объяснение и повторное открытие из истории.

Карта MapLibre загружается только для результата с координатами. Дни и альтернативы
используют сохранённые снимки; для демо остаётся список. Подложка OpenStreetMap
включается кнопкой. Пунктир — порядок POI, не дорога. Worker включается в Next-сборку.
После обновления выполнить `npm ci`, затем пересобрать и перезапустить frontend.
Тесты модели карты требуют Node 22.6+ с `--experimental-strip-types` (проверено 22.15.0).
Подробности: [route-map.md](../docs/route-map.md), [приёмка](../docs/acceptance.md).
